# Контрольные чеклисты для извлечения знаний

## Pre-Extraction Checklist

- [ ] Книга конвертирована в markdown (UTF-8)
- [ ] Структура книги понятна (оглавление, части, главы)
- [ ] Книга прочитана полностью или по частям
- [ ] Выделены основные разделы и главы
- [ ] Определён тип книги (предметная область × режим аргументации)

## Per-Category Extraction Checklist

### Нарративная дуга
- [ ] Для каждой главы сформулирован one-sentence summary
- [ ] Определён главный тезис каждой главы
- [ ] Определены логические переходы между главами
- [ ] Определены напряжения/вопросы, которые главы создают и разрешают
- [ ] Сформулирована главная мысль автора (one sentence)

### Главные идеи
- [ ] Выделены главные идеи из каждой главы
- [ ] Идеи записаны в формате шаблона
- [ ] Проверена связь идей между главами
- [ ] Определена центральная идея книги

### Проблемы
- [ ] Выделены проблемы, которые решает книга
- [ ] Выделены проблемы, которые описывает книга
- [ ] Проблемы записаны с контекстом и решениями
- [ ] Определены проблемы при применении методологии

### Предпосылки
- [ ] Выделены явные предположения автора
- [ ] Выделены неявные предположения автора
- [ ] Определены условия применимости методологии
- [ ] Предпосылки записаны с контекстом

### Последствия
- [ ] Выделены описанные последствия применения
- [ ] Определены потенциальные последствия
- [ ] Последствия записаны с контекстом
- [ ] Определены риски применения

### Методология
- [ ] Выделены пошаговые процессы
- [ ] Выделены методы и техники
- [ ] Выделены инструменты и подходы
- [ ] Методология записана в формате инструкций
- [ ] Определены условия применения методологии

## Structuring Checklist

- [ ] Выбрана правильная структура документа (A: Каталог или B: Понимание)
- [ ] Создан документ знаний по выбранному шаблону
- [ ] Все категории знаний заполнены
- [ ] Добавлены метаданные книги (автор, год, тип, режим аргументации)
- [ ] Добавлено краткое резюме
- [ ] Определено практическое применение
- [ ] Указаны связи с другими источниками
- [ ] Добавлены важные цитаты

## Категоризация

- [ ] Каждая единица имеет единый ID + первичную категорию (мульти-категория разрешена — вторичные списком, без плодежа дублей)
- [ ] На каждой единице висит сквозной тег темы (`#…`) для дедупликации кросс-batch
- [ ] Опциональные категории (Patterns/Recipes, Антипаттерны) добавлены, если книга их даёт
- [ ] Пустые категории (типично «Предпосылки» для индуктивных/методологических книг) оставлены пустыми или помечены, а не заполнены банальностями
- [ ] Чанки очищены от шума (URL, колонтитулы, вклеенные оглавления, справочные перечни) до извлечения
- [ ] При слиянии дублей по тегу темы сохранены ВСЕ уникальные якорные цитаты (не выбрана одна)
- [ ] Мета-уровневые единицы («автор о конструкции книги») помечены `[мета-уровень]`, не смешаны с предметными
- [ ] Patterns/Антипаттерны — как вторичная категория к идее/методологии где уместно, а не дубль-единицы

## Fan-out integrity (для длинных книг)

- [ ] Каждый reader верифицировал, что его batch-файл непуст — до возврата «готово»
- [ ] Синтезатор проверил наличие и непустоту ВСЕХ `batch_*.md` перед сборкой
- [ ] При отсутствии/пустом батче — явный СТОП, а не молчаливая подстановка пропуска

## Cognitive Quality Audit

Каждое извлечённое знание проверяется по пяти принципам:

### Принцип 1: Контекст и Применимость
- [ ] Определена целевая аудитория (Novice/Pro)
- [ ] Определено состояние читателя (Crisis/Growth/Stacking)
- [ ] Определена цель потребления (Solve/Learn/Confirm)

### Принцип 2: Типология Пользы
- [ ] Определён тип полезного действия:
  - **Функциональная:** Улучшает процесс, экономит ресурсы
  - **Социальная:** Повышает статус, авторитет, аргументацию
  - **Психологическая:** Снижает тревогу, даёт уверенность
  - **Нормативная/Ethical:** Меняет понимание долга/ответственности
- [ ] Если автор вводит свою типологию пользы — использована она с пометкой `[по автору]`

### Принцип 3: Синтаксис Действия
- [ ] Тест на визуализацию: Можно ли изобразить концепт как сцену?
- [ ] Грамматика: Субъект + Глагол + Объект (не абстракции)
- [ ] Приземление: Абстрактные принципы имеют конкретные примеры (Case Studies)

### Принцип 4: Armament Test
- [ ] Можно ли использовать это знание как аргумент в дискуссии?
- [ ] Знание содержит достаточно контекста, чтобы быть убедительным без книги
- [ ] Знание не является банальностью — с учётом целевой аудитории единицы (Novice/Pro); «банальность + нетривиальное условие применимости» проходит

### Принцип 5: Укоренённость (Groundedness)
- [ ] Каждое интерпретативное утверждение (тезис, инсайт, «что опровергает») заякорено — прямая цитата со ссылкой на главу/страницу ИЛИ пометка `[интерпретация]`
- [ ] Цитата-факт отделена от цитаты-оценки/гиперболы автора (`[оценка автора]`)
- [ ] Проведена граница между «автор сказал буквально» и «я вывел по контексту»
- [ ] Маркер `[интерпретация]` / `[оценка автора]` **дошёл до финального документа** (синтезатор не вычистил его)
- [ ] Нет утверждений, приписанных автору без опоры на текст
