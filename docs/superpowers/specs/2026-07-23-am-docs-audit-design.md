# am-docs-audit — дизайн навыка «чистоты» харнесса

**Дата:** 2026-07-23
**Статус:** approved (brainstorming 2026-07-23) → ждёт ревью файла → `writing-plans`
**Дом навыка:** `agent-knowledge/skills/am-docs-audit/SKILL.md`
**Трек:** Knowledge-Meta (рядом с `prune`, `improve-skill`, `decisions`)

---

## 1. Контекст и проблема

Харнесс Astra уже имеет механизм гигиены — но только на половине территории. В
`agent-knowledge/USAGE.md` есть раздел «Поддержка (governance)»: `prune` (сторты),
`rotate-skill-runs`, `auto-retrieve`, `lint-portability`, regression-evals. Однако
**документационный слой мета-репо Astra** — четыре перекрывающихся входных документа
(`HARNESS.md`, `README.md`, `AGENTS.md`, `CLAUDE.md`), hot-канал `CONTEXT.md`, реестры
в `meta/` — **не подчиняется никакой гигиене**. Именно туда смотрит пользователь.

Находки разведки (с доказательством):

| Проблема | Доказательство |
|---|---|
| Нет канон-владельца «кто чем владеет» | File-Map в `CLAUDE.md` перечисляет **4** файла, реально в корне **6+** (нет `HARNESS.md`, `README.md`, `jtbd-snapshot.yml`) |
| STALE в живом навигационном доке | `README.md` ссылается на `meta/reference/` «в разработке» — **папки не существует** |
| Дрифт таблиц файлов | CLAUDE.md=4, README.md=12, HARNESS.md=6 — три разных частичных ответа |
| Мёртвый артефакт-кандидат | `jtbd-snapshot.yml` (36 КБ, 9 июля) — **0 ссылок** из других доков; JTBD-дерево декомпозировано в strategy-docset 17 июня |
| Дублирование | таблицы «что где» одновременно в HARNESS.md и README.md; go-lib/data-flow — и в PM.md, и в AGENTS.md |

`am-skills` (GitLab) и `agent-knowledge` (GitHub) — два разных репо, оба «репо скиллов».
Это **намеренное разделение** (мои скиллы vs командные AM-скиллы) — НЕ дефект,
закодировано как declared exception (см. §4).

## 2. Лучшие практики (фундамент)

Из исследования (dev.to, danielvaughan.com, Atlassian SSOT, Falconer) + наблюдения:

1. **Каноничный SoT + тонкие указатели.** `AGENTS.md` — универсальный стандарт (Linux
   Foundation, 60k+ проектов, читают Codex/Cursor/Claude/Aider); agent-specific файлы
   (`CLAUDE.md`) — симлинк или одна строка делегирования, **без копирования**.
2. **Дрифт — главный враг.** «Файлы гниют как любые доки; неверная инструкция хуже
   отсутствия». Нужен **регулярный детектор**, не разовая уборка.
3. **Слои, не плоско.** global → root → subdir; конкретный слой *дополняет*, не заменяет.
4. **Терсе и императивно.** Каждый токен грузится каждый ход; `AGENTS.md` желательно
   <150 строк; конкретные правила, не «пиши чистый код».
5. **Не автогенерить инструкционные файлы.** LLM-авторизованные *хуже* ручных (−success,
   +20% cost). → детект → отчёт → правка **с одобрением человека**.
6. **Консолидация без maintenance-layer стопорится.** (Falconer: «док перестаёт быть
   точным через пару месяцев».) → **сам скилл и есть maintenance-layer.**

## 3. Архитектурное решение

**Подход:** ownership/layering-модель живёт **секцией в `AGENTS.md`** (канон,
агенто-независимый SoT), новых файлов **не плодим**. `CLAUDE.md` худеет до тонкого
указателя (делегирует в `AGENTS.md` + Claude-специфика: branch, auth, PM-routing).

Почему не отдельный `meta/context-map.md`: это плодило бы ровно ту сущность-указатель,
которую лечим. Раз `AGENTS.md` — канон, которому все указывают, ownership-карта
принадлежит туда. `AGENTS.md` сейчас ~62 строки; секция (+30) держится в лимите <150.

**Agent-agnostic (принцип харнесса):** навык использует только generic-операции
(`test`/`grep`/`diff`/read), проходит `lint-portability.py`. Сам объект аудита
агенто-независим: `AGENTS.md` — канон, agent-specific файлы обязаны быть тонкими
указателями. Портабельность — проверяемый инвариант (`NON-CANONICAL-CONFIG`).

## 4. Ownership-модель (содержимое секции в AGENTS.md)

| Файл | Слой | Владелец (concern) |
|---|---|---|
| `AGENTS.md` | root | **канон SoT**: продукт + архитектура для агента + эта ownership-секция |
| `CLAUDE.md` | root | тонкий конфиг Claude Code: указатели, PM-rules, branch, auth → делегирует в AGENTS.md |
| `HARNESS.md` | root | онбординг человека: что поставить, день-1 по ролям |
| `README.md` | root | инженерно-операционный гайд: клон/синк/refresh-AGENTS |
| `CONTEXT.md` | root | HOT-канал: активные задачи, open questions (пишут агенты) |
| `repos.yml` | root | реестр репозиториев — единственный список (`.gitignore` генерится отсюда) |
| `meta/research-index.md` | meta | реестр исследований |
| `meta/skills-guide.md` | meta | routing «хочу X → скилл Y» |
| `meta/repos/*.md` | meta | профили сервисов (49 шт.) |
| `PM/` | subrepo | дом продуктовых артефактов (отдельный GitLab); карта — `PM/CLAUDE.md` |
| `agent-knowledge/` | sibling | **мои** скиллы + сторы знаний (GitHub) |
| `am-skills/` | sibling | **командные** AM-скиллы (GitLab) |
| `NMT-Canon/` | symlink | внешняя методология (read-only, CC BY-NC-SA) |

**Правило слоёв:** global (`~/.claude/CLAUDE.md`) → Astra root → subrepo (`PM/`).
Конкретный слой *дополняет*, никогда не заменяет вышестоящий.

**Declared exceptions (НЕ флаговать):**
- `agent-knowledge/` ↔ `am-skills/` — два репо скиллов by design (мои vs AM).
- `NMT-Canon/` — внешний read-only.

## 5. Навык `am-docs-audit`

**Дом:** `agent-knowledge/skills/am-docs-audit/SKILL.md` (как все am-*). Агенто-независимый
(generic-операции только, проходит `lint-portability.py`). Операционный → носит
learning-footer + пишет строку в `state/skill-runs.md`.

**Зонтик:** `am-docs-audit` — единый вход «почисти весь харнес». Свои 8 сигналов док-слоя —
его новая ценность; сторы (`learnings/`+`decisions/`) — **делегирует скиллу `prune`**, не
дублирует логику. В SKILL.md прописан шаг «по завершении doc-скана вызвать `prune` (в том
же режиме) и влить его findings в отчёт».

**Режимы:**

| Режим | Что делает | По умолчанию |
|---|---|---|
| `check` | Сканирует док-слой по 8 сигналам + **вызывает `prune` в check-режиме**, сливает всё в один отчёт с предложенными действиями. Ничего не меняет. | ✅ дефолт (без аргумента) |
| `fix` | По каждому флагу — предложенный diff + AskUserQuestion (remove/keep/update/merge/archive); применяет одобренное; в конце зовёт `prune` в интерактивном режиме. Коммит — по запросу. | по явному `fix` |

**Аудит-поверхность:**

| В скопе | Вне скопа (и почему) |
|---|---|
| Astra root: `*.md` + `*.yml` (вкл. `jtbd-snapshot.yml` как DEAD-ARTIFACT-кандидат) | Кодовые саб-репо (`agent/`, …) — граница мета-репо |
| `meta/*.md` + реальная структура `meta/` (сверка с деревом в README) | per-repo `AGENTS.md` в коде — их ведёт `refresh-agents`/`collect-repo-facts` |
| Ownership-секция в `AGENTS.md` = **контракт** (источник, не цель аудита) | Глубокий аудит `PM/` и `agent-knowledge` внутрянки — отдельные репо со своей гигиеной |
| Cross-ref-разрешение в сиблинги (`agent-knowledge/`, `am-skills/`, `NMT-Canon/`) + проверка declared-exceptions | Авто-консолидация / авто-переписывание доков — запрещено (практика №5) |

**Вывод:** каждая находка = `{файл · сигнал · доказательство · предложенное действие}`.
`check` → отчёт; `fix` → diff + AskUserQuestion по каждой. Доки — **НЕ append-only**
(в отличие от сторов): правка обычная, но каждое изменение — с одобрением человека.

## 6. Сигналы (8)

M = механический (скриптуемый/CI-gate); J = суждение (агент + человек).

| # | Сигнал | Проверка | M/J |
|---|---|---|---|
| 1 | `STALE-REF` | Из доков достаём path-токены (`` `meta/…` ``, markdown-ссылки), `test -e` по правильному корню (Astra / agent-knowledge / `~`) | **M** |
| 2 | `MISSING-OWNER` | `ls` root+meta `.md/.yml` ↔ распарсенная ownership-таблица AGENTS.md, в обе стороны (файл без строки / строка без файла) | **M** |
| 3 | `TABLE-DIVERGENCE` | listing-блок в доке (File-Map, дерево структуры) ↔ реальный `find` каталога; перечислен-но-нет / есть-но-не-перечислен | **M** |
| 4 | `NON-CANONICAL-CONFIG` | agent-specific файл (`CLAUDE.md` и др.) содержит секцию, совпадающую по теме с AGENTS.md, без делегирования → нарушение портабельности | M+J |
| 5 | `DUPLICATION` | Один и тот же факт в 2+ входных доках; grep-эвристика по канон-фактам → кандидат на ревью | **J** |
| 6 | `LAYER-VIOLATION` | Нижний слой (PM/CLAUDE.md и т.п.) пересказывает/противоречит root-AGENTS вместо указателя | **J** |
| 7 | `DEAD-ARTIFACT` | Стрейт/бэкап-файлы (`*.bak`, `harness1.excalidraw`, untracked-мусор в meta/) — **M**; рассуждение «superseded, но не в archive» (`jtbd-snapshot.yml`) — **J** | M+J |
| 8 | `RELEVANCE` | ref-count (`grep -rl`, 0 = сильный dead-prior) + mtime (тай-брейкер) — **M**; redundancy (пересечение с каноном) + necessity (уникальный concern) — **J**. → KEEP/TRIM/MERGE-в-X/ARCHIVE/SPLIT | M+J |

**Линия раздела** (как у `prune`/`am-research-index`): механика — автоматически, суждение —
только по подсвеченному. Три сигнала (1, 2, 3) полностью детерминированы → будущий CI-гейт.
Остальные — семантика, агент подсвечивает кандидатов, решение за человеком.

**Возраст один никогда не флагует** — только изменение (та же формула, что у `prune`).

## 7. Lifecycle

**Когда звать:**
- после реорганизации док-слоя (добавили/удалили root/meta-файл, перенесли PM-артефакт);
- после рефактора, удалившего/переименовавшего файлы, на которые ссылаются доки;
- перед онбордингом (HARNESS/README достойны доверия) и перед релизом;
- периодически как health-check (`check` дёшев).

**Фазирование (YAGNI):**
- **P1 (строим):** скилл `am-docs-audit` — `check` + `fix`, со всеми 8 сигналами, зовёт
  `prune`. Достаточно, чтобы держать харнес в чистоте.
- **P2 (опционально, когда сигналы устаканятся):** `meta/scripts/docs_audit.py` — CI-гейт
  только по механическому подмножеству (сигналы 1, 2, 3), exits non-zero. Как
  `capability_registry_check.py` / `lint-portability.py`. **Строить сейчас не надо.**

**Запись / state:** `check` по умолчанию печатает в чат; опционально пишет
`meta/reports/docs-audit-YYYY-MM-DD.md` (зеркало `refresh-agents` → `refresh-summary-…`).

## 8. Non-goals

- Кодовые саб-репо и их per-repo `AGENTS.md` — вне (их ведёт `refresh-agents`).
- Авто-генерация/переписывание инструкционных файлов — запрещено (практика №5).
- Глубокий аудит `PM/` и `agent-knowledge` внутрянки — отдельные репо со своей гигиеной.
- Не удаляет и не переписывает публикуемые доки без явного одобрения каждого изменения.

## 9. Открытые вопросы / future

- **P2 CI-гейт** `docs_audit.py` по сигналам 1/2/3 — отложить до стабилизации сигналов.
- **CONTEXT.md bloat** как soft-signal (hot-канал разрастается → предложить архивировать
  старые секции в `meta/archive/`) — контентно-зависимая эвристика, пока НЕ в ядре.
- Имя команды: `am-docs-audit` (префикс `am-` = домен Astra-Monitoring, «привязан к
  харнесс»; разрабатывается в `agent-knowledge/skills/`, публикуется в `am-skills`).
