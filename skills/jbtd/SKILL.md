# jbtd и заголовки

## Overview

Два связанных ремесла на одном стержне — инфостиле Ильяхова / редакции Бюро:

1. **jbdt-формулировка** пользовательской задачи.
2. **Заголовок** статьи, лендинга, анонса функции.

Оба рождаются из одних и тех же кирпичей: **факт, конкретика, польза конкретному
читателю**. Часто по одной задаче нужно и то, и другое — тогда заголовок выводится
из jbdt, а не придумывается отдельно.

**Главный принцип:** оценка не убеждает — убеждает факт. Оценочные слова
(«удобный», «эффективный», «быстро», «выгоднее») — яд. Каждое оценочное слово
надо заменить измеримым фактом: цифрой, сроком, проверяемым состоянием или
конкретной сценой.

Опорные материалы и дословные цитаты — в `sources.md`.

## Когда использовать

- Нужно сформулировать пользовательскую задачу в формате jbdt.
- Нужно придумать или переделать заголовок/заголовки.
- Нужно и то и другое по одной задаче («напиши jbdt и заголовок»).
- Проверяете чужую jbdt или заголовок на прочность.

## Когда НЕ использовать

- Сбор pains/jobs из транскрипта встречи — там свой навык (`am-pain-mining`).
- Написание полной спецификации/PRD — `spec-writing` / `am-write-specs`.
- Креативный копирайтинг, слоганы, нейминг — здесь принцип обратный: нам нужна
  прямая польза, а не игра слов.

## Ядро: пять принципов

Всё ниже держится на этих пяти. Они работают **и для jbdt, и для заголовков**.

1. **Факты вместо оценок.** Оценочное прилагательное — сигнал к переработке:
   удалить или раскрыть через измеримый факт. «Быстро» → «за 5 секунд»;
   «удобный» → «без переключения между вкладками».
2. **Чувственная вообразимость («внутренний фильм»).** Каждую часть формулировки
   можно представить как конкретную сцену — картинку, действие, объект на экране.
   Абстракции («нагрузка», «оптимизация», «эффективность») нельзя представить →
   им нельзя поверить.
3. **Потребность/тема, а не инструмент.** Описывайте задачу, а не способ её
   решения. «Хочу калькулятор» — решение; «хочу понять, выгодно ли переходить» —
   задача.
4. **Польза конкретному читателю + его язык.** Один человек в одной ситуации,
   слова, которыми он реально мыслит. Не «для всех / любая задача».
5. **Ясность и прямота.** Без креатива, метафор, каламбуров, рифм, клише,
   канцелярита, рекламных штампов. Понятность важнее красоты.

## Главный рычаг: чёрный список оценочных слов

Это самый частый провал (в baseline — 18 случаев из ~30). Прогоняйте через этот
список **каждую** формулировку и заголовок перед сдачей.

**Стоп-слова (оценки без меры):** быстро, вовремя, медленно, адекватный,
разумный, понятный, реальный, справедливый, обоснованный, приемлемый, качественный,
удобный, эффективный, полноценный, полный, надёжный, современный, инновационный,
оптимальный, профессиональный, мощный, гибкий, выгоднее, дешевле, лучше, круче,
выигрывает, премиальный, эксклюзивный, уникальный.

**Правило замены:** для каждого стоп-слова спросите «какой факт за этим стоит?»
и впишите измеримое:

| Стоп-слово | Замена (факт) |
|---|---|
| быстро | за 5 секунд / одним взглядом / в один экран |
| вовремя | до демо / до конца спринта / до 18:00 пятницы |
| адекватная цена | цена в диапазоне медианы по сопоставимым объявлениям |
| выгоднее / дешевле | окупается за N месяцев / в 3 раза дороже при покупке, но в 10 раз меньше ест |
| понятный / удобный | с указанием ставки и базы / без переключения между вкладками |
| качественный свет | яркость от 500 люкс, цветопередача 90+ |
| реальная цена | средняя цена по 20 последним объявлениям в моём городе |
| без сюрпризов | фиксированная сумма — N ₽ в месяц |

Если факта нет в контексте — его надо добыть (см. «Перед формулировкой») или
убрать слово. Оставлять оценку «для красоты» нельзя.

## Ремесло 1. jbdt-формулировка

### Шаблон

> **Когда [ситуация], я хочу [мотивация], чтобы [ожидаемый результат].**

### Наполнение частей

- **Когда [ситуация] = СЦЕНАРИЙ.** Один-два живых узнаваемых момента из реального
  опыта пользователя: конкретное время, место, действие, проблема. Сжимайте до
  ключевого момента (5–8 слов), **не пересказывайте условие дословно**. На языке
  пользователя. Очевидное противоречие оговорите прямо («хоть и дороже»).
- **я хочу [мотивация] = ПОТРЕБНОСТЬ, не инструмент.** Конкретное действие, которое
  можно представить. Весь спектр мотиваций: функциональные, эмоциональные,
  социальные — если они реальны. Без оценочных слов.
- **чтобы [ожидаемый результат] = ПРОВЕРЯЕМАЯ ПОЛЬЗА.** Измеримый исход: цифра,
  срок, проверяемое состояние. Должен логически отвечать на вопрос «как?», который
  возникает после мотивации. Не «чтобы всё было хорошо».

### Пошаговый алгоритм

1. **Поймите задачу.** Выразите суть одним-двумя простыми предложениями. Не
   получается — вы ещё не поняли реальную задачу пользователя (это симптом
   непонимания, не нехватки вдохновения).
2. **Определите читателя и его язык.** Кто этот человек, в какой момент, какими
   словами мыслит. Сузьте до одного человека, не «для всех».
3. **Черновик по шаблону.** Заполните Когда / хочу / чтобы.
4. **Вычистите оценки.** Прогоните через чёрный список стоп-слов, каждое замените
   фактом (цифра / срок / сцена).
5. **Тест «внутренний фильм».** По каждой из трёх частей: «могу ли представить
   это конкретной сценой?». Нет — переписывайте в конкретику.
6. **Уточните.** Конкретизируйте аудиторию, добавьте измеримый результат, условие.
   Точность усиливает попадание.
7. **Проверьте на дубль.** Если выдаёте несколько формулировок — у каждой должна
   быть другая потребность (другой момент / actor / результат), а не только
   другой синтаксис. Перефраз одной задачи — это дубль, не вторая задача.
8. **Связка «как?».** После «хочу…» должен возникать вопрос «как?», на который
   отвечает блок «чтобы…». Разрыв — формулировка не закончена.
9. **Вычитка.** Перечитайте вслух. Выловите языковые сбои, канцеляризм, пропущенные
   оценки. Без этого шага сдавать нельзя.

### Примеры: плохо → хорошо

**Плохо (из baseline):**
> Когда я выставляю свой старый iPhone на продажу на Авито, я хочу **быстро**
> понять его **реальную рыночную** цену, чтобы поставить **адекватную** сумму и
> продать без лишних торгов за **разумное** время.

4 стоп-слова, ничего измеримого. **Хорошо:**
> Когда выставляю старый iPhone на Авито, я хочу увидеть диапазон цен по таким же
> моделям в моём городе за последнюю неделю, чтобы поставить цену, по которой
> телефон купят за 7 дней.

«Быстро» убрано; «реальная рыночная» → «диапазон цен по сопоставимым за неделю»;
«разумное время» → «за 7 дней».

**Плохо:**
> Когда стоимость налогов скачет, я хочу получать **понятную** оценку
> **налоговой нагрузки**, чтобы вести учёт **без сюрпризов**.

Оценки + абстракция + штамп. **Хорошо:**
> Когда закрываю налоги по салону и не знаю итоговую сумму, я хочу увидеть расчёт
> налога к уплате до 25 числа, чтобы отложить нужную сумму и не ловить кассовый
> разрыв в день платежа.

«Понятную» убрано; «налоговая нагрузка» → «налог к уплате»; «без сюрпризов» →
«отложить сумму до 25 числа».

## Ремесло 2. Заголовок

### Заголовок зависит от контекста (жанра)

Правила ниже написаны для **заголовка статьи / лендинга / анонса**: он продаёт
пользу читателю. Но «заголовок» бывает разный, и рамка зависит от жанра —
сначала определите жанр, потом выбирайте рамку.

| Контекст | Что называет заголовок | Откуда брать |
|---|---|---|
| Статья, лендинг, анонс функции | Пользу читателю (что получит / сможет сделать) | Выводится из пользы JBTD («чтобы…») |
| Задача, issue, summary в таск-трекере, заголовок PR | Работу (что делаем / меняем) | По названию работы; польза остаётся в JBTD |

**Для задачи заголовок = название работы**, а не польза пользователя. Не выводите
benefit из блока «чтобы…» в заголовок задачи: польза живёт в JBTD, заголовок
задачи говорит, **что меняется**. «Улучшение» — не-слово (что именно лучше?), но и
benefit-формулировка как `summary` задачи — ошибка жанра: это питч пользы, а не
имя работы.

Одна и та же фраза может быть верной для одного жанра и ошибочной для другого:

| Жанр | Плохо (не та рамка) | Хорошо |
|---|---|---|
| Задача (Jira `summary`) | Найти нужный дашборд: фильтры, поиск и дерево папок | Интерфейс списка дашбордов: фильтры, поиск и дерево папок |
| Статья / лендинг | Интерфейс списка дашбордов: фильтры, поиск и дерево папок | Найти нужный дашборд среди десятков: фильтры, поиск и дерево папок |

### Правила

- **Прямо называет тему с первого взгляда.** Читатель должен понять, о чём речь,
  без расшифровки. Заголовок отвечает на «о чём это?».
- **Понятность важнее креатива.** Никаких антитез с дефисом («Дорогая сейчас —
  выгоднее потом»), рифмованных пар («Не продешевить и не прогадать»), ритмических
  балансов, фразеологизмов («как на ладони»). Тест: **«есть ли здесь ход/приём?»**
  — если да, переписать в прямую номинацию.
- **Опора на пользу конкретному читателю**, а не на продукт. «Что читатель получит
  / сможет сделать», а не «что мы запускаем». Не заголовок-анонс функции.
- **Извлекайте конкретику-цифру из контекста.** «Фиксированная сумма» → с цифрой;
  «дороже» → с ценами. Конкретные детали делают заголовок сильнее.
- **Сужайте аудиторию.** «Для салонов красоты» — категория; «бухгалтер для салона
  красоты» — конкретный читатель. Сужение усиливает попадание.
- **Разговорный человеческий язык.** Без канцелярита («бухгалтерское сопровождение»,
  «с указанием») и жаргонизмов («фикс-платёж»).

### Прогрессия уточнения

От общего — к сильному через конкретику:

1. `Бухгалтер` — слишком общо.
2. `Бухгалтер для салона красоты` — уже конкретный читатель.
3. `Бухгалтер для салона красоты. Первичка и учёт за N ₽ в месяц` — плюс
   измеримая польза.

Каждый шаг уточнения (аудитория, условие, цифра) усиливает заголовок.

### Примеры: плохо → хорошо

**Плохо:**
> Дорогая сейчас — выгоднее потом: почему светодиодные лампы обходятся дешевле
> ламп накаливания

Антитеза-приём + «выгоднее/дешевле» без цифр. **Хорошо:**
> Светодиодная лампа за 200 ₽ против лампы накаливания за 20 ₽: что дешевле за год

Прямая тема + конкретные цены; ход убран.

**Плохо:**
> Спринт как на ладони: новый обзор статуса в таск-трекере

Клише + анонс функции. **Хорошо:**
> Кто чем занят и что зависло: новый обзор статуса спринта

Прямая польза читателю (что он увидит), без фразеологизма.

**Плохо:**
> Не продешевить и не прогадать: как поставить справедливую цену на б/у вещь

Рифмованная пара + «справедливую». **Хорошо:**
> Как узнать среднюю цену б/у вещи по объявлениям в вашем городе и поставить свою

## Когда нужно и jbdt, и заголовок

Часто просят оба артефакта по одной задаче. Делайте заголовок **производным от
jbdt**, а не отдельной выдумкой:

1. Сначала jbdt — она фиксирует задачу и измеримую пользу (блок «чтобы…»).
2. Заголовок соберите из двух опор jbdt: **кто + в какой ситуации** (из «Когда…»)
   и **какая измеримая польза** (из «чтобы…»).
3. Прогоните заголовок через правила ремесла 2.

Так заголовок автоматически про пользу читателя, а не про инструмент (провал №7
исключён структурно).

**Важно: это рецепт для заголовка статьи/лендинга.** Если просят заголовок
задачи / issue / PR — он называется **по работе**, а не по пользе JBTD: польза
остаётся в JBTD, заголовок задачи говорит, что меняется (см. «Заголовок зависит
от контекста» выше). Шаг 2 тут не подходит: не тяните «чтобы…» в `summary`.

| Провал | Признак | Лекарство |
|---|---|---|
| Оценочные прилагательные без меры | «быстро», «адекватную», «выгоднее», «справедливую» | Чёрный список стоп-слов → замена фактом |

| Benefit-заголовок у задачи (смешение жанров) | «Найти нужный дашборд…» как `summary` задачи | Это заголовок статьи; для задачи назовите работу: «Интерфейс списка дашбордов…» |
| Эмоциональный результат | «не нервничать», «спокойно», «не продешевить» в блоке «чтобы» | Проверяемое состояние вместо эмоции |

| Языковой сбой | Английское слово в русском тексте («пауsmarty»), опечатки | Латиница-сканер: ни одного русского слова с латиницей внутри (бренды/аббревиатуры ок); реальный прогон, не «я вычитал» |
| Несогласованность лица | «Когда закупщик видит… я хочу…» (3-е → 1-е) | Всё от первого лица «я» |

## Тесты самопроверки

Прежде чем сдать, прогоните формулировку/заголовок через **все** тесты поочерёдно.
Не пишите «проверил» — реально прогоните текст по каждому пункту.

- **Стоп-слово-сканер:** есть ли слово из чёрного списка? Для каждого — факт.
- **Латиница-сканер (для русского текста):** ни одного русского слова с латиницей
  внутри. Бренды и аббревиатуры (iPhone, LED, CRM, B2B, KPI) — ок. Слово вроде
  «пауsmarty» — сбой, пересоберите.
- **Внутренний фильм:** каждую часть можно представить как сцену?
- **Ход/приём?** (для заголовка): убрать все образные слова — стало сильнее?
- **Одно лицо (для jbdt):** все три части от первого лица «я»; нет смешения
  «когда закупщик видит… я хочу».
- **Не пересказ условия:** «Когда» — ключевой момент, а не копия исходного
  сценария. Сравните с условием — если совпадает дословно, сжимайте до 5–8 слов.
- **Новая задача или та же?** (для нескольких jbdt): отличающийся actor/момент/результат?
- **Разные углы (для набора заголовков):** каждый вариант отличается углом или
  пользой, а не только концовкой — иначе это дубли.
- **Как?** (для jbdt): блок «чтобы» отвечает на вопрос после «хочу»?
- **Цель или решение?**: описана потребность, а не инструмент?

## Чек-лист jbdt

- [ ] Тема ясна с первого взгляда.
- [ ] «Когда» — живой сценарий (сжатый, не пересказ условия), на языке пользователя.
- [ ] «Хочу» — потребность, а не инструмент; конкретное действие.
- [ ] «Чтобы» — измеримая, проверяемая польза (цифра/срок/состояние).
- [ ] Нет стоп-слов; каждое заменено фактом.
- [ ] Каждую часть можно представить как сцену.
- [ ] Если несколько формулировок — у каждой другая потребность.
- [ ] «Чтобы» отвечает на «как?» после «хочу».
- [ ] Единое первое лицо («я») во всех трёх частях; нет смешения лиц.
- [ ] Латиница-сканер пройден (нет русских слов с латиницей внутри).
- [ ] Очевидное противоречие раскрыто прямо.
- [ ] Прочитано вслух, реально прогнано по всем тестам выше.

## Чек-лист заголовка

- [ ] Прямо называет тему с первого взгляда.
- [ ] Нет хода/приёма (антитезы, рифмы, фразеологизма).
- [ ] Фокус на пользе читателю, а не на продукте/анонсе.
- [ ] Конкретика-цифра извлечена из контекста, где она есть.
- [ ] Аудитория сужена до конкретного читателя.
- [ ] Нет стоп-слов; разговорный язык без канцелярита и жаргона.
- [ ] Уточнён по сравнению с базовой версией (аудитория/условие/цифра).

## Common mistakes

| Mistake | Fix |
|---|---|
| Заполнить шаблон оценочными словами «для красоты» | Каждое оценочное слово → измеримый факт; иначе убрать |
| Выдать две jbdt, которые — одна задача | Проверить корневую потребность; перефраз = дубль |
| Креативный заголовок вместо прямого | Тест «ход/приём?» → прямая номинация темы |
| Скопировать условие в «Когда…» | Сжать до ключевого момента |
| Инструмент вместо потребности | Спросить «какую задачу решает пользователь?» |
| Эмоция в блоке «чтобы» | Заменить на проверяемое состояние |
| Сдать без вычитки | Прочитать вслух, прогнать стоп-сканер |

## Rules

- **Факт вместо оценки.** Каждое оценочное слово — кандидат на удаление или замену
  измеримым фактом.
- **Понятность важнее креатива.** Никаких метафор, рифм, антитез, клише — ни в
  jbdt, ни в заголовке.
- **Задача, а не инструмент.** Формулируйте потребность, а не способ решения.
- **Конкретный читатель и его язык.** Один человек, один момент, не «для всех».
- **Измеримый результат.** Блок «чтобы» и ядро заголовка — проверяемая польза.
- **Одна задача на формулировку.** Дубли-перефразы — не отдельные задачи.
- **Первое лицо.** jbdt — от «я» («Когда я…, я хочу…, чтобы…»); не смешивайте
  лица в одном предложении («когда закупщик видит… я хочу» — сбой).
- **Разные углы в наборе.** Несколько заголовков на одну тему должны отличаться
  углом или пользой, а не только концовкой — иначе это дубли.
- **Обязательная вычитка** по чек-листу, стоп-сканеру и латиница-сканеру перед
  сдачей. Сказать «вычитал» — мало: реально прогоните текст по каждому тесту.
- **Не копируйте примеры из скилла дословно.** Примеры иллюстрируют принцип;
  адаптируйте формулировку к реальному сценарию задачи.
- **Пишите на языке задачи пользователя.** Русская задача — русская формулировка
  и заголовок; английская — английские.
