# 📚 Book Conversion and Knowledge Extraction Standard

## 🎯 Цель документа

Создать единый стандарт для конвертации книг из различных форматов (.doc, .docx, .pdf, .fb2) в читабельный markdown формат с последующим извлечением главных идей, проблем, предпосылок, последствий, методологии и инсайтов для практического применения.

**Основные задачи:**
1. Конвертация книг в структурированный markdown формат с сохранением структуры и форматирования
2. Извлечение ключевых знаний: идеи, проблемы, методологии, инсайты
3. Структурирование извлеченных знаний для практического применения
4. Создание базы знаний из книг для дальнейшего использования

---

## 🔄 Процесс конвертации книги

### Этап 1: Discovery Phase (Обязательно)

**Цель:** Определить тип документа и выбрать подходящий метод конвертации.

#### 1.1 Анализ структуры файла

**Действия:**
- [ ] Определить формат исходного файла (.doc, .docx, .pdf, .fb2)
- [ ] Проанализировать структуру файла (OLE2 потоки для .doc, ZIP структура для .docx)
- [ ] Проверить метаданные документа (автор, дата создания, количество страниц)
- [ ] Определить кодировку файла

**Команды для анализа:**
```bash
# Проверка типа файла
file book.doc

# Анализ структуры .doc (OLE2)
python3 -c "import olefile; ole = olefile.OleFileIO('book.doc'); print(ole.listdir())"

# Проверка метаданных
python3 scripts/extract_metadata.py book.doc
```

#### 1.2 Определение типа содержимого

**Действия:**
- [ ] Проверить наличие текстового содержимого
- [ ] Проверить наличие изображений
- [ ] Определить тип документа:
  - **Текстовый** - содержит читаемый текст
  - **Отсканированный** - содержит только изображения страниц
  - **Смешанный** - содержит текст и изображения

**Проверка:**
```bash
# Попытка извлечения текста
antiword book.doc | head -20

# Проверка наличия изображений
python3 scripts/check_images.py book.doc
```

#### 1.3 Валидация метаданных

**Действия:**
- [ ] Проверить достоверность метаданных
- [ ] Сравнить метаданные с реальной структурой документа
- [ ] Если метаданные показывают мало слов/символов → проверить тип документа

**Критерии валидации:**
- Если метаданные показывают < 1000 слов для книги → вероятно отсканированный документ
- Если размер файла большой (> 5MB) но слов мало → проверить наличие изображений

### Этап 2: Research Phase (Обязательно)

**Цель:** Исследовать доступные методы и выбрать подходящий.

#### 2.1 Матрица совместимости методов

| Метод | Формат .doc (OLE2) | Формат .docx | Формат .pdf | Изображения | Текст | OCR |
|-------|-------------------|--------------|-------------|-------------|-------|-----|
| **LibreOffice+Pandoc** | ✅ | ✅ | ✅ | ✅ | ✅ | ⚠️ |
| **antiword** | ✅ | ❌ | ❌ | ⚠️ | ✅ | ❌ |
| **mammoth** | ❌ | ✅ | ❌ | ⚠️ | ✅ | ❌ |
| **textract** | ⚠️ | ✅ | ✅ | ⚠️ | ✅ | ⚠️ |
| **Tesseract OCR** | ❌ | ❌ | ✅ | ✅ | ✅ | ✅ |

#### 2.2 Выбор метода на основе типа документа

**Матрица выбора метода:**

| Тип документа | Формат | Рекомендуемый метод | Альтернатива |
|--------------|--------|---------------------|--------------|
| Текстовый | .doc (OLE2) | LibreOffice+Pandoc | antiword |
| Отсканированный | .doc (OLE2) | LibreOffice+Pandoc + OCR | Tesseract OCR |
| Смешанный | .doc (OLE2) | LibreOffice+Pandoc | - |
| Текстовый | .docx | Pandoc | mammoth, textract |
| Отсканированный | .docx | Pandoc + OCR | Tesseract OCR |
| Текстовый | .pdf | Pandoc | textract |
| Отсканированный | .pdf | Tesseract OCR | - |

### Этап 3: Conversion Phase

**Цель:** Конвертировать книгу в markdown формат.

#### 3.1 Процесс конвертации LibreOffice+Pandoc (Рекомендуемый)

**Шаги:**
```bash
# Шаг 1: Конвертация .doc → .docx через LibreOffice
libreoffice --headless --convert-to docx book.doc

# Шаг 2: Конвертация .docx → .md через Pandoc
pandoc book.docx -o book.md --extract-media=images

# Шаг 3: Проверка результата
head -50 book.md
```

#### 3.2 Процесс конвертации antiword (Альтернатива для текстовых .doc)

**Шаги:**
```bash
# Конвертация .doc → .txt
antiword book.doc > book.txt

# Конвертация .txt → .md (требует ручной обработки)
# Используется только если LibreOffice недоступен
```

#### 3.3 Обработка отсканированных документов

**Шаги:**
```bash
# Шаг 1: Извлечение изображений страниц
libreoffice --headless --convert-to pdf book.doc
pdfimages -all book.pdf page

# Шаг 2: OCR обработка каждой страницы
for page in page-*.ppm; do
    tesseract $page ${page%.ppm} -l rus+eng
done

# Шаг 3: Объединение текста в markdown
cat page-*.txt > book.md
```

### Этап 4: Validation Phase

**Цель:** Проверить качество конвертации.

#### 4.1 Структурная валидация

**Проверка заголовков:**
```bash
# Подсчет заголовков разных уровней
grep -c "^# " book.md
grep -c "^## " book.md
grep -c "^### " book.md
```

**Проверка списков:**
```bash
# Подсчет списков
grep -c "^- " book.md
grep -c "^[0-9]\. " book.md
```

**Проверка таблиц:**
```bash
# Подсчет таблиц
grep -c "^|" book.md
```

**Проверка изображений:**
```bash
# Подсчет ссылок на изображения
grep -c "!\[" book.md

# Проверка существования файлов изображений
grep -o "!\[.*\](.*)" book.md | sed 's/.*(\(.*\))/\1/' | while read img; do
  if [ ! -f "$img" ]; then
    echo "Missing image: $img"
  fi
done
```

#### 4.2 Качественная валидация

**Проверка читаемости:**
- [ ] Открыть файл в markdown редакторе
- [ ] Прочитать несколько разделов
- [ ] Проверить визуальное отображение
- [ ] Проверить навигацию по документу

**Проверка сохранения содержимого:**
```bash
# Подсчет слов в исходном и итоговом файле
wc -w book.doc book.md

# Проверка соответствия (±5%)
# Если разница > 5% → требуется дополнительная проверка
```

**Проверка кодировки:**
```bash
# Проверка кодировки
file -I book.md

# Должно быть: text/plain; charset=utf-8
```

## 🧠 Процесс извлечения знаний из книги

### Этап 1: Первичное чтение и структурирование

**Цель:** Понять структуру книги и выделить основные разделы.

#### 1.1 Анализ структуры книги

**Действия:**
- [ ] Прочитать оглавление (если есть)
- [ ] Определить основные разделы и главы
- [ ] Выделить ключевые темы каждой главы
- [ ] Создать карту структуры книги

**Формат карты структуры:**
```markdown
# Структура книги: [Название]

## Часть 1: [Название]
- Глава 1: [Тема]
- Глава 2: [Тема]

## Часть 2: [Название]
- Глава 3: [Тема]
- Глава 4: [Тема]
```

#### 1.2 Выделение ключевых концепций

**Действия:**
- [ ] Выписать основные термины и определения
- [ ] Выделить ключевые концепции и модели
- [ ] Отметить важные цитаты и формулировки

**Формат записи концепций:**
```markdown
## Ключевые концепции

### [Название концепции]
- **Определение:** [определение]
- **Контекст:** [где используется]
- **Важность:** [почему важно]
- **Цитата:** "[цитата из книги]"
```

### Этап 2: Извлечение главных идей

**Цель:** Вычленить главные идеи книги для практического применения.

#### 2.1 Категории извлекаемых знаний

**1. Главные идеи:**
- Ключевые мысли и выводы автора
- Основные тезисы книги
- Центральные концепции

**2. Проблемы:**
- Проблемы, которые решает книга
- Проблемы, которые описывает книга
- Проблемы, которые возникают при применении методологии

**3. Предпосылки:**
- Предположения автора
- Условия применимости методологии
- Контекст, в котором работает подход

**4. Последствия:**
- Результаты применения методологии
- Последствия принятия идей
- Влияние на практику

**5. Методология:**
- Пошаговые процессы
- Методы и техники
- Инструменты и подходы

**6. Инсайты:**
- Неожиданные открытия
- Контринтуитивные идеи
- Важные озарения

#### 2.2 Framework "Cognitive Quality" (Когнитивное качество знаний)

**Принцип 1: Контекст и Применимость**
Знание не существует в вакууме. Для каждой извлеченной идеи необходимо определить границы её применимости.
- **Целевая аудитория:** Для какого уровня подготовки (Novice/Pro)?
- **Состояние читателя:** В какой ситуации это работает? (Crisis/Growth/Stacking)
- **Цель потребления:** Зачем это нужно? (Solve/Learn/Confirm)

**Принцип 2: Типология Пользы (Utility Taxonomy)**
Классификация полезного действия знания:
1.  **Функциональная (Functional):** Улучшает процесс, экономит ресурсы.
2.  **Социальная (Social):** Повышает статус, авторитет, аргументацию.
3.  **Психологическая (Psychological):** Снижает тревогу, дает уверенность, развлекает.

**Принцип 3: Синтаксис Действия (Actionable Syntax)**
Знание должно быть сформулировано так, чтобы его можно было "увидеть".
- **Тест на визуализацию:** Можно ли изобразить этот концепт как сцену?
- **Грамматика:** Субъект + Глагол + Объект. Избегаем абстракций ("Оптимизация") в пользу действий ("Директор сокращает").
- **Приземление:** Абстрактные принципы должны иметь конкретные примеры (Case Studies).

#### 2.3 Формат извлечения знаний


**Шаблон для каждой категории:**

```markdown
## [Категория]: [Название]

### Контекст
- **Глава/Раздел:** [где находится]
- **Страница:** [номер страницы, если есть]

### Содержание
[Описание идеи/проблемы/методологии]

### Практическое применение
- **Когда использовать:** [условия применения]
- **Как применять:** [пошаговый процесс]
- **Ожидаемый результат:** [что получим]

### Связи
- **Связано с:** [другие идеи/концепции]
- **Противоречит:** [если есть противоречия]
- **Дополняет:** [если дополняет другие идеи]

### Цитата
"[прямая цитата из книги]"
```

#### 2.3 Процесс извлечения по категориям

**Для каждой категории выполнить:**

1. **Главные идеи:**
   - [ ] Прочитать каждую главу и выделить 1-3 главные идеи
   - [ ] Записать идеи в формате шаблона
   - [ ] Проверить связь идей между главами

2. **Проблемы:**
   - [ ] Выделить проблемы, которые решает книга
   - [ ] Выделить проблемы, которые описывает книга
   - [ ] Записать проблемы с контекстом и решениями

3. **Предпосылки:**
   - [ ] Выделить явные и неявные предположения автора
   - [ ] Определить условия применимости методологии
   - [ ] Записать предпосылки с контекстом

4. **Последствия:**
   - [ ] Выделить описанные последствия применения
   - [ ] Определить потенциальные последствия
   - [ ] Записать последствия с контекстом

5. **Методология:**
   - [ ] Выделить пошаговые процессы
   - [ ] Выделить методы и техники
   - [ ] Выделить инструменты и подходы
   - [ ] Записать методологию в формате инструкций

6. **Инсайты:**
   - [ ] Выделить неожиданные открытия
   - [ ] Выделить контринтуитивные идеи
   - [ ] Выделить важные озарения
   - [ ] Записать инсайты с контекстом и применением

### Этап 3: Структурирование извлеченных знаний

**Цель:** Организовать извлеченные знания для практического применения.

#### 3.1 Создание документа знаний

**Структура документа:**

```markdown
# Извлеченные знания: [Название книги]

## Метаданные
- **Автор:** [автор]
- **Год издания:** [год]
- **Дата извлечения:** [дата]
- **Источник:** [путь к markdown файлу]

## Краткое резюме
[2-3 абзаца о главной идее книги]

## Главные идеи
[список главных идей по шаблону]

## Проблемы
[список проблем по шаблону]

## Предпосылки
[список предпосылок по шаблону]

## Последствия
[список последствий по шаблону]

## Методология
[список методологий по шаблону]

## Инсайты
[список инсайтов по шаблону]

## Практическое применение
### Когда использовать эту книгу
[условия применения знаний из книги]

### Как применять знания
[пошаговый процесс применения]

### Связи с другими источниками
[ссылки на другие книги/методологии]

## Цитаты
[важные цитаты из книги]
```

#### 3.2 Создание базы знаний

**Если обрабатывается библиотека книг:**

**Структура базы знаний:**
```
knowledge_base/
├── books/
│   ├── book1/
│   │   ├── book1.md (конвертированная книга)
│   │   ├── book1_knowledge.md (извлеченные знания)
│   │   └── images/ (изображения)
│   └── book2/
│       ├── book2.md
│       ├── book2_knowledge.md
│       └── images/
├── index.md (индекс всех книг)
└── topics/
    ├── methodology.md (методологии из всех книг)
    ├── problems.md (проблемы из всех книг)
    └── insights.md (инсайты из всех книг)
```

## ✅ Чеклист конвертации книги

### Pre-Conversion Checklist

- [ ] Определен формат исходного файла
- [ ] Проанализирована структура файла
- [ ] Определен тип документа (текстовый/отсканированный/смешанный)
- [ ] Проверен тип содержимого (текст/изображения/оба)
- [ ] Валидированы метаданные документа
- [ ] Исследованы доступные методы конвертации
- [ ] Проверена совместимость методов с форматом
- [ ] Документированы ограничения методов
- [ ] Выбран подходящий метод на основе анализа
- [ ] Подготовлен план конвертации

### Structural Requirements

#### Заголовки и иерархия
- [ ] Все заголовки конвертированы в markdown формат (#, ##, ###, etc.)
- [ ] Иерархия заголовков сохранена (H1 > H2 > H3 > H4)
- [ ] Нет пропущенных заголовков
- [ ] Нет дублирующихся заголовков
- [ ] Структура документа логична и читаема

#### Параграфы и текст
- [ ] Все параграфы сохранены
- [ ] Пустые строки между параграфами добавлены
- [ ] Форматирование текста сохранено (жирный, курсив)
- [ ] Специальные символы обработаны корректно
- [ ] Кодировка UTF-8

#### Списки
- [ ] Все нумерованные списки конвертированы (1., 2., 3.)
- [ ] Все маркированные списки конвертированы (-, *, +)
- [ ] Вложенность списков сохранена
- [ ] Отступы в списках корректны

#### Таблицы (если есть)
- [ ] Все таблицы конвертированы в markdown формат
- [ ] Структура таблиц сохранена
- [ ] Выравнивание колонок сохранено
- [ ] Заголовки таблиц выделены

#### Изображения
- [ ] Все изображения извлечены из документа
- [ ] Изображения сохранены в отдельную папку (например, `images/`)
- [ ] Ссылки на изображения созданы в формате `![alt](path)`
- [ ] Все ссылки на изображения работают
- [ ] Alt-текст для изображений добавлен

#### Ссылки

## 🔍 Protocol Challenge: Анализ скрытых предположений

**Применение Protocol Challenge для выявления скрытых предположений и потенциальных проблем:**

### Предположение 1: Все книги имеют текстовое содержимое
**Контринтуитивная перспектива:** Многие старые книги могут быть отсканированными изображениями без текстового слоя.

**Скрытое предположение:** Мы предполагаем, что книги содержат читаемый текст, который можно извлечь.

**Реальность:** Отсканированные книги требуют OCR обработки, что значительно усложняет процесс.

**Решение:** Добавлен этап Discovery для определения типа документа перед конвертацией.

### Предположение 2: Извлечение знаний - объективный процесс
**Контринтуитивная перспектива:** Извлечение знаний - субъективный процесс, зависящий от интерпретации читателя.

**Скрытое предположение:** Мы предполагаем, что все читатели извлекут одинаковые знания из книги.

**Реальность:** Разные читатели могут выделить разные идеи и инсайты в зависимости от контекста и опыта.

**Решение:** Использование структурированного шаблона и чеклиста для обеспечения полноты извлечения.

### Предположение 3: Автоматическая конвертация всегда работает
**Контринтуитивная перспектива:** Автоматическая конвертация может потерять важные элементы форматирования или структуры.

**Скрытое предположение:** Мы предполагаем, что автоматические инструменты сохраняют все элементы книги.

**Реальность:** Сложное форматирование, таблицы, изображения могут требовать ручной доработки.

**Решение:** Добавлен этап Validation с чеклистами для проверки всех элементов.

### Предположение 4: Извлеченные знания готовы к применению
**Контринтуитивная перспектива:** Извлеченные знания могут быть неполными или требовать дополнительного контекста для применения.

**Скрытое предположение:** Мы предполагаем, что извлеченные знания можно сразу применять на практике.

**Реальность:** Знания требуют адаптации к конкретному контексту и могут нуждаться в дополнительной информации.

**Решение:** Добавлены разделы "Практическое применение" и "Условия применения" в шаблон извлечения знаний.

## 🚨 Риски и ограничения

### Риски конвертации

1. **Старый формат .doc может быть не полностью поддерживаемым**
   - **Решение:** Использовать LibreOffice+Pandoc как универсальный метод

2. **Изображения могут быть встроены в документ и требуют извлечения**
   - **Решение:** Использовать Pandoc с опцией `--extract-media`

3. **Сложное форматирование может быть потеряно**
   - **Решение:** Документировать ограничения и использовать ручную доработку при необходимости

4. **Специальные символы могут требовать ручной обработки**
   - **Решение:** Проверять кодировку и использовать UTF-8

### Риски извлечения знаний

1. **Субъективность извлечения знаний**
   - **Решение:** Использовать структурированный шаблон и проверять полноту

2. **Неполное извлечение знаний**
   - **Решение:** Использовать чеклист и проверять все категории

3. **Неправильная интерпретация идей**
   - **Решение:** Использовать прямые цитаты и проверять контекст

### Ограничения

1. Некоторые элементы форматирования Word могут не иметь аналогов в markdown
2. Сложные таблицы могут требовать ручной доработки
3. Изображения требуют отдельного хранения
4. Извлечение знаний требует времени и внимательного чтения
