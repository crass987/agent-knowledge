# am-esp-check — проверка ЕСПД по РД СМК.037-02-2021

Проверяет доки сертификационного комплекта AM (конвейер `PM/initiatives/cert-agent`:
`sections/*.md` → pandoc → DOCX) на соответствие корпоративному стандарту оформления
Астры. Полный текст РД: `PM/initiatives/cert-agent/references/rd-smk037.md`;
выжимки из образцов-картинок: `references/rd-smk037-images/EXTRACT-*.md`;
формальный чек-лист: `references/rd-smk037-checklist.md`.

Все пути ниже — от `/Users/CraSS/Documents/Code_projects/Astra/`.

## Рабочий процесс

### 1. Автоматическая проверка (обязательно)

```bash
cd PM/initiatives/cert-agent
make check DOC=02-program/<NAME>     # сборка должна быть свежей: make doc DOC=… перед этим
# или напрямую:
python3 build/check-rd037.py --md out/<NAME>.md --docx out/<NAME>.docx
```

- Доки «на графах» (спецификация, ВЭД, УД — РД 14): `make check` подхватит `layout: graph`
  из meta.yaml автоматически; прямым вызовом — флаг `--graphdoc` (отключает подписи таблиц,
  нумерацию подразделов, перечень сокращений строками).
- `make check` также передаёт `--meta` (meta.yaml) — сверка СТРУКТУРЫ разделов с ГОСТ-каноном
  docmap.md (DX-130/131: нет обязательного раздела / лишний H1).
- Сборка (`make doc` / `assemble.sh`) автоматически: титул по В.2, ЛУ отдельным файлом,
  ЛРИ последним листом (кроме УД), рамка-штамп, таблицы по 9.9.5, перечисления по 9.5,
  аннотация до содержания, кэш NUMPAGES фактическим числом листов (fill-numpages.py).
- `--report FILE` — дописать отчёт прогона в markdown-файл (для согласований/ДИБ);
  сводный отчёт комплекта: `out/rd037-report.md`.
- `error` — блокирует коммит; `warn` — разбор по контексту (часто легитимно).
- Каждая находка несёт пункт РД — сверяйся с `references/rd-smk037.md`.
- Выходной код 1 = есть error. CI-джобу ставить на это условие.

Если док не собран — собрать: `make doc DOC=02-program/<NAME>`.

### 2. Глазные проверки DOCX (скрипт не видит)

Открыть DOCX (LibreOffice) и проверить по чек-листу `references/rd-smk037-checklist.md`
раздел «глаз/Word»:

- заголовок не оторван от текста, нет одиночных строк абзаца на границе страниц (5.3.5–5.3.6);
- TOC заполнен (Word/LO обновляет поля при открытии), уровни ≤ 4, аннотация/содержание/
  лист регистрации изменений в содержание НЕ входят (8.4, 8.7);
- таблицы: двойная линия после строки заголовка (`w:val="double"` sz=4, inline),
  высота строк ≥ 8 мм, шрифт Sans 10–11, шапка по центру (9.9.5);
- титульный лист по В.2 (рамка-штамп слева, «Утвержден …-ЛУ», «Листов N», год ОДИН раз
  внизу листа), колонтитул по рис. 1; в Word проверить: поля обновились при открытии
  (updateFields) и границы таблиц на месте (гоча порядка OOXML — см. чек-лист);
- **рамка-штамп** (титул В.2 / ЛУ В.1): прибита к НИЖНЕМУ краю текстовой полосы
  (`vertAnchor="margin" tblpYSpec="bottom"`), выровнена по левому краю
  (`tblpXSpec="left"`), текст в ячейках `align=left`. ⚠ `vertAnchor="page"`+`tblpY`
  в LO не работает (игнор/перетекание на 2-й лист) — см. чек-лист «Рамка-штамп»;
- **таблицы в md**: разделитель обязан быть валидным (`---`, `:--`, `--:`, `:--:`),
  число ячеек = числу колонок шапки — иначе pandoc не парсит, и в DOCX/ODT таблица
  остаётся текстом (видна разметка `|…|`). См. чек-лист «Гоча markdown-таблиц»;
- превью на macOS: `bash build/preview-pdf.sh out/<NAME>.docx /tmp` (Sans→Arial в копии;
  CoreText macOS не регистрирует TTF PT Astra Sans/Serif из deb 1.003).

### 3. LLM-проход по стилистике (9.1–9.2)

Правила, которые не формализуются регэкспами — проверить чтением:

- обязательные требования словами «должен/следует/не допускается» (9.1.5);
- указания в повелительном наклонении: «Нажать…», «Закрыть…» (9.1.4);
- описание результата — совершенный глагол, процесса — несовершенный (9.2.2–9.2.3);
- «ввести/выбрать/установить-снять» для полей и списков (9.2.6);
- названия элементов интерфейса = названиям в самой программе, без синонимов (9.1.8);
- единообразие терминологии по всему доку (9.1.1 «согласованность»).

### 4. Что делать с находками

- Правится исходник `sections/*.md` (НЕ собранный DOCX), затем пересборка и повторный
  прогон до 0 error.
- Настройки оформления (шрифты/поля/интервалы) живут в
  `build/make-reference-docx.py` → `templates/reference.docx`; пост-обработка
  (титульник, колонтитул, NBSP, перечни) — в `build/title-page-docx.py`.
- Новое правило добавлять в `build/check-rd037.py` с ID (MD-xxx — текст, DX-xxx —
  оформление) и пунктом РД; если правило глазное — в чек-лист.

## Известные ограничения

- PT Astra Fact / PT Mono установлены и рендерятся; ⚠ PT Astra Sans/Serif (deb
  fonts-pt-astra_1.003) macOS CoreText не регистрирует — превью через preview-pdf.sh
  (подмена на Arial), финальные PDF на машине, где шрифт загружается (Linux/Word).
- TOC в DOCX: статичный кэш заполняется `fill-numpages.py` (LO-рендер → номера);
  в ODT — `fill-odt-toc.py` (`make odt`): нативный `<text:table-of-content>` с
  `index-title-template` «Содержание» + кэш записей в нативных стилях `Contents_20_N`;
  ⚠ LO при `--convert-to odt` выносит кэш TOC обычными параграфами ПОСЛЕ блока —
  `strip_dangling_toc` удаляет висячие (иначе дубль записей). updateFields в settings.xml —
  в позиции по схеме CT_Settings, не первым!
- Формат вывода конвейера — DOCX (канон) + ODT (`make odt`, целевой формат владельца);
  финальные PDF — руками из Word/LibreOffice с обновлением полей.
- Правила кнопок `[Сохранить]` и клавиш `<Ctrl>` в md: `**[Сохранить]**`,
  `**<Ctrl>**` (9.13.8–9.13.9).
