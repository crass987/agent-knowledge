## Фаза 0: Приобретение источника

### Матрица источников

| Источник | Аудио-канал | Визуальный канал | Инструменты |
|----------|-------------|-------------------|-------------|
| **YouTube URL** | yt-dlp субтитры → you-tldr fallback → parakeet-mlx fallback | yt-dlp thumbnails + извлечение ключевых кадров | yt-dlp, ffmpeg, parakeet-mlx |
| **Локальное видео** (.mp4, .mkv, .mov) | parakeet-mlx → WhisperNotes fallback | Ключевые кадры через ffmpeg | parakeet-mlx, ffmpeg |
| **Транскрипт** (.srt, .vtt, .txt) | Прямое чтение | Недоступно (если видео не предоставлено) | Read tool, MCP vision |
| **Только аудио** (.mp3, .m4a) | parakeet-mlx → WhisperNotes fallback | Недоступно | parakeet-mlx |

### Аудио-канал

**Приоритет получения транскрипта:**

1. **yt-dlp субтитры** (YouTube) — скачать `.vtt`/`.srt`, очистить HTML + дубликаты
2. **Веб-сервис транскрипции** (YouTube) — you-tldr.com/transcript/{video_id}. Быстро, чистый результат, но нужен интернет и доступ к сервису
3. **parakeet-mlx** (автоматический, Apple Silicon) — `parakeet-mlx audio.mp3`. NVIDIA Parakeet TDT 0.6B v3, 25 языков, точность на уровне Whisper Large V3, скорость ~30x реального времени на Apple Silicon. Выводит SRT/VTT/TXT/JSON. Установка: `uv tool install parakeet-mlx -U`
4. **WhisperNotes** (ручной) — открыть аудио/видео в приложении, экспортировать транскрипт как SRT/TXT

**Результат:** чистый транскрипт с временными метками на уровне предложений

```bash
# YouTube: проверить и скачать субтитры
yt-dlp --list-subs URL
yt-dlp --write-sub --sub-lang en,ru --convert-subs srt URL
yt-dlp --write-auto-sub --sub-lang en,ru --convert-subs srt URL  # автогенерированные

# Извлечение аудио (если субтитров нет)
yt-dlp -x --audio-format mp3 URL
ffmpeg -i video.mp4 -vn -acodec mp3 audio.mp3  # из локального файла

# Parakeet-mlx транскрипция (Apple Silicon)
parakeet-mlx audio.mp3                        # по умолчанию → SRT
parakeet-mlx audio.mp3 --output-format txt    # чистый текст
parakeet-mlx audio.mp3 --output-format json   # с word-level timestamps

# Очистка VTT/SRT
sed 's/<[^>]*>//g' subtitles.vtt > clean.txt
```

### Очистка дубликатов в автосубтитрах YouTube

YouTube auto-captions используют **rolling captions** — формат progressive reveal. Каждый SRT-блок содержит предыдущий текст + новую фразу (накопительный). Между реальными блоками стоят «переходные кадры» длительностью ~10мс.

**Пример структуры:**
```
Блок 1:  [00:00 → 00:02.23]  "A few months ago, I wrote a few"        ← реальный (2.2 сек)
Блок 2:  [00:02.23 → 00:02.24]  "A few months ago, I wrote a few"     ← переходный (10мс, skip)
Блок 3:  [00:02.24 → 00:04.75]  "A few months ago, I wrote a few\nsentences, about four sentences, that"  ← реальный
```

Уникальный контент — **последняя строка** каждого реального блока. Переходные блоки (duration < 100мс) — мусор.

**Порядок действий:**

1. Скачать автосубтитры через yt-dlp
2. Применить парсер rolling captions:

```bash
# Скрипт в skills/video-knowledge-extraction/scripts/srt-clean.py
python3 ~/.claude/skills/video-knowledge-extraction/scripts/srt-clean.py subtitles.srt transcript.txt
```

Скрипт автоматически:
- Пропускает переходные кадры (duration < 100мс)
- Извлекает последнюю строку каждого реального блока (новый контент)
- Склеивает orphan-фрагменты (edge case: пустая строка в первом блоке)

3. Проверить: прочитать начало результата — первая фраза не должна быть обрезана, фразы не должны повторяться

### Визуальный канал

**Принцип:** Визуальный канал — это не иллюстрации к транскрипту. Это **независимый источник знаний** (диаграммы, модели, демо), из которого извлекаются знания, отсутствующие в аудио. Но ROI визуала зависит от типа видео.

**Три уровня визуального канала:**

| Уровень | Типы видео | Что делать | Почему |
|---------|-----------|-----------|--------|
| **Полный** (извлечь + классифицировать + включить в документ) | Tutorial/Demo, Review/Analysis, Short/Clip | Скачать видео → ffmpeg → filter-talking-heads → MCP классификация → включить в документ | Визуал = основной источник знаний. Транскрипт неполный без него. |
| **Лёгкий** (извлечь кадры, не классифицировать) | Lecture/Educational | Скачать видео → ffmpeg → filter-talking-heads → кадры лежат в keyframes/ | Спикер озвучивает слайды — визуал обычно подтверждает, а не добавляет. Кадры доступны для анализа по запросу. |
| **Пропустить** | Interview/Podcast, Vlog/Narrative | Не скачивать видео, не извлекать кадры | Talking head, визуальных знаний нет |

**Лёгкий режим для лекций — почему:**
Тест на 40-мин лекции Карпаты: 40 минут визуальной обработки, ~55K токенов → 3 из 14 кадров содержали уникальное знание, остальные — подтверждение устного контента. ROI: 5-10% уникальных знаний за 60-70% времени обработки. Кадры сохраняются в `keyframes/` — пользователь может запросить полный визуальный анализ позже.

### Процесс для «Полного» уровня (Tutorial/Demo, Review, Short)

1. Скачать видео: `yt-dlp -f "best[height<=720]" URL -o video.mp4`
2. Извлечь ключевые кадры: `ffmpeg -i video.mp4 -vf "select=gt(scene\,0.4)" -vsync vfr keyframes/scene_%04d.png`
3. Запустить `filter-talking-heads.py --delete` для удаления talking heads
4. MCP-классификация оставшихся кадров (batch по 5-10):
   > "Classify these 5 video frames. For each: talking head (skip) or contains visual knowledge (describe). Return as numbered list."
5. Для каждого кадра, включаемого в документ — **Read tool** проверка:
   - **Условие A:** Нет человека крупным планом, содержимое читаемо
   - **Условие B:** Содержимое кадра совпадает с темой секции, куда он помещается
6. Результат: Индекс визуальных знаний + inline-изображения в документе

```bash
# Полный процесс
yt-dlp -f "best[height<=720]" URL -o video.mp4
ffmpeg -i video.mp4 -vf "select=gt(scene\,0.4)" -vsync vfr keyframes/scene_%04d.png
python3 ~/.claude/skills/video-knowledge-extraction/scripts/filter-talking-heads.py keyframes/ --delete --verbose
```

### Процесс для «Лёгкого» уровня (Lecture)

1. Скачать видео: `yt-dlp -f "best[height<=720]" URL -o video.mp4`
2. Извлечь ключевые кадры: `ffmpeg -i video.mp4 -vf "select=gt(scene\,0.5)" -vsync vfr keyframes/scene_%04d.png`
3. Запустить `filter-talking-heads.py --delete`
4. **Всё.** Кадры лежат в `keyframes/`. Не классифицировать, не включать в документ.
5. В документе знаний секция «Визуальные знания» помечается:
   > «Кадры извлечены в `keyframes/` ({N} файлов). Визуальный анализ не проводился (тип видео: Lecture). Запросите анализ при необходимости.»

```bash
# Лёгкий процесс (Lecture)
yt-dlp -f "best[height<=720]" URL -o video.mp4
ffmpeg -i video.mp4 -vf "select=gt(scene\,0.5)" -vsync vfr keyframes/scene_%04d.png
python3 ~/.claude/skills/video-knowledge-extraction/scripts/filter-talking-heads.py keyframes/ --delete --verbose
```

### Процесс для «Пропустить» (Interview, Vlog)

Не скачивать видео, не извлекать кадры. Секция «Визуальные знания»:
> «Недоступно (тип видео: Interview/Podcast — визуальных знаний нет)»

### Оптимизация для полного уровня

**Threshold по типу видео:**

| Тип | Threshold | Почему |
|-----|-----------|--------|
| Tutorial/Demo | `0.4` | Демо = частая смена экрана |
| Review/Analysis | `0.4` | Графики и скриншоты — умеренная смена |
| Short/Clip | periodic каждые 30 сек | Короткое видео — periodic лучше |

**Batch классификация через MCP:**
Группировать кадры по 5-10 в один вызов `mcp__zai-mcp-server__analyze_image`:
> "Classify these 5 video frames. For each: talking head (skip) or contains visual knowledge (describe). Return as numbered list."

**Two-pass для длинных видео (>30 мин):**
```
Pass 1 (coarse): 1 кадр каждые 120 сек → классифицировать через MCP → найти «интересные» регионы
Pass 2 (fine): scene-detection ТОЛЬКО в интересных регионах → 30-50 кадров вместо 150+
```

**Почему скрипт + визуальная проверка:** Скрипт ловит ~60% talking heads (close-ups), но пропускает split-view (спикер + слайд на фоне — формат YC/TED) и даёт false negatives. Для видео в формате YC/TED скрипт может удалить 0 кадров — в этом случае **вся ответственность на визуальной проверке** (Read tool для каждого кадра, включаемого в документ). **Скрипт — фильтр первого прохода, Read tool — финальная проверка.**

### Логика принятия решения

1. YouTube URL → скачать субтитры (если есть), иначе you-tldr fallback → parakeet-mlx fallback → визуальный канал по уровню (Полный / Лёгкий / Пропустить)
2. Локальное видео → parakeet-mlx + визуальный канал по уровню
3. Транскрипт (.srt/.vtt/.txt) → прямое чтение, визуальный канал недоступен
4. Только аудио → parakeet-mlx, визуальный канал недоступен

### Шлюз качества (перед Фазой 1)

- [ ] Транскрипт чистый (без HTML-артефактов субтитров, без повторов Whisper)
- [ ] Визуальный канал выполнен по уровню:
  - **Полный** (Tutorial/Demo, Review, Short): видео скачано, кадры извлечены и классифицированы
  - **Лёгкий** (Lecture): видео скачано, кадры извлечены в `keyframes/`, talking heads удалены скриптом
  - **Пропущен** (Interview/Podcast, Vlog/Narrative): видео не скачивалось
- [ ] Длительность видео определена
- [ ] Количество говорящих определено (для интервью/подкастов)

## Фаза 1: Картирование контента

В отличие от книг, видео не имеют оглавления. Навык должен **вывести** структуру.

### 1.1 Классификация типа видео

Определите тип — это определяет стратегию извлечения:

| Тип | Описание | Стратегия извлечения |
|-----|----------|---------------------|
| **Lecture/Educational** | Один спикер обучает теме | Временные темы, слайды как структурные маркеры |
| **Interview/Podcast** | Два или более спикера в разговоре | Тематические повороты, точки согласия/несогласия |
| **Review/Analysis** | Оценка продукта/идеи/события | Критерии оценки, выводы, рекомендации |
| **Tutorial/Demo** | Пошаговая демонстрация | Последовательность действий, визуальные демо как основное знание |
| **Vlog/Narrative** | Личная история, опыт | Таймлайн, ключевые повороты, lessons learned |
| **Short/Clip** | До 3 минут, высокая плотность | Одна тема, быстрое извлечение |

Результат классификации записывается в метаданные документа знаний.

### 1.2 Вывод структуры (Виртуальные главы)

Из транскрипта определить тематические сегменты:

- Искать переходные фразы ("Now let's talk about...", "Moving on to...", "Переходя к...")
- Визуальные изменения (новый слайд, переключение на демо) как границы сегментов
- Для интервью: смена говорящего как потенциальные границы
- Результат: Список тематических сегментов с временными метками начала и конца

````markdown
## Виртуальные главы

- [00:00–02:30] Introduction and context
- [02:30–08:15] Core concept: X
- [08:15–12:00] Case study: Y
- [12:00–15:00] Practical application
- [15:00–18:30] Q&A / Discussion
````

### 1.3 Оценка информационной плотности

Оценить, какая часть видео — контент vs. заполнитель:
- **Высокая плотность:** Лекция с плотным материалом, мало повторений. Компрессия умеренная.
- **Средняя плотность:** Типичный подкаст/интервью. Компрессия стандартная.
- **Низкая плотность:** Влог, много повторений, отклонения от темы. Агрессивная компрессия.

Оценка плотности определяет уровень компрессии в Фазе 2 — видео с низкой плотностью сжимаются агрессивнее.

**Для чего:** 30-минутное видео с высокой плотностью может дать документ знаний на 5 минут чтения. То же видео с низкой плотностью — на 2-3 минуты. Цель: документ всегда плотнее источника.

## Фаза 2: Извлечение знаний

### 2.1 Когнитивное качество (Cognitive Quality)

Каждое извлечённое знание проверяется по четырём принципам — тем же, что и в навыке для книг:

**Принцип 1: Контекст и Применимость**
- Целевая аудитория: Novice / Pro
- Состояние читателя: Crisis / Growth / Stacking
- Цель потребления: Solve / Learn / Confirm

**Принцип 2: Типология Пользы (Utility Taxonomy)**
- **Функциональная:** Улучшает процесс, экономит ресурсы
- **Социальная:** Повышает статус, авторитет, аргументацию
- **Психологическая:** Снижает тревогу, даёт уверенность, развлекает

**Принцип 3: Синтаксис Действия (Actionable Syntax)**
- Тест на визуализацию: Можно ли изобразить концепт как сцену?
- Грамматика: Субъект + Глагол + Объект. Не абстракции.
- Приземление: Абстрактные принципы должны иметь конкретные примеры

**Принцип 4: Armament Test**
Можно ли использовать это знание как аргумент в дискуссии? Банальности ("надо планировать") не проходят.

### 2.2 Категории извлечения (адаптированные для видео)

| Категория | Адаптация для видео |
|-----------|-------------------|
| **Главные идеи** | Компрессия повторений — спикеры повторяют ключевые мысли 2-3 раза. Извлечь один раз. |
| **Проблемы** | Проблема = конкретная ситуация, где кто-то **не может достичь цели**. Описание характеристик (например, «LLM имеют когнитивные дефициты») — это не проблема, а идея. Проблема: «Разработчик не может верифицировать diff в 10 000 строк». |
| **Предпосылки** | В видео предпосылки часто неявные — спикер принимает их без озвучивания |
| **Последствия** | Без изменений |
| **Методология** | Для туториалов/демо: визуальная последовательность ЕСТЬ методология. Извлечь шаги из визуального канала. |
| **Инсайты** | Пометить: был инсайт вербальным (🗣) или визуальным (👁) |

### Правила качества содержания

**1. Дедупликация:** Одна и та же мысль не может появляться в двух секциях. Если «когнитивные дефициты LLM» описаны в «Проблемах» — не повторять в «Инсайтах». Выбрать одну секцию для каждой мысли.

**2. Banality test (усиленный):** Если инсайт звучит как заголовок TechCrunch или общеизвестный talking point — это не инсайт. Примеры того, что **не проходит**: «программирование на английском ломает барьеры», «AI изменит всё», «нужно быть осторожным с AGI». Тест: если вы можете представить это как заголовок статьи на Хабре — удалите.

**3. Визуальное знание vs визуальное подтверждение:**
- **Визуальное знание** = знание, которого **НЕТ** в аудио. Диаграмма, модель, визуальное сравнение, которые спикер не описывает устно.
- **Визуальное подтверждение** = кадр, содержание которого полностью описано в транскрипте. Слайд, который спикер читает вслух. Скриншот, который спикер описывает.
- **Правило:** В секцию «Визуальные знания» включать **только** визуальные знания. Визуальные подтверждения помечать как «подтверждает [ссылка на идею]» и включать в inline-изображения, но **не** в секцию «Визуальные знания».

**Тест «закрой транскрипт» (обязательный для каждого кадра в секции «Визуальные знания»):**
Закройте транскрипт. Посмотрите на кадр. Можете ли вы описать его содержание по памяти транскрипта? Если да — это визуальное подтверждение, а не знание. Визуальное знание = вы НЕ МОЖЕТЕ восстановить содержание кадра из памяти транскрипта (например, диаграмма архитектуры, которую спикер не описывал подробно; визуальное сравнение «до/после»; модель, показанная без устного пояснения).

**4. Inline-изображения — проверка перед включением:** Перед добавлением `![...](keyframes/...)` в документ — **открыть файл через Read tool** и проверить два условия:

**Условие A — talking head:** На кадре нет человека крупным планом. Содержимое читаемо (диаграмма, слайд, код).
**Условие B — контекстное совпадение:** Содержимое кадра **совпадает с темой секции**, в которую вы его помещаете. Если кадр показывает «Build for agents», а секция называется «Iron Man suit» — кадр в неправильном месте. Найдите секцию, тему которой он изображает, или не включайте.

**Оба условия обязательны. Невыполнение любого = кадр не включается.**

### 2.3 Принцип компрессии

**Правило:** Документ знаний должен быть плотнее исходного видео. 30-минутное видео → документ знаний на 3-5 минут чтения.

Это ключевое отличие от навыка для книг (где документ ~1:10 размера книги). Видео имеет более низкую информационную плотность, поэтому компрессия агрессивнее (~1:6–1:10 времени чтения).

Как применять компрессию:
- Удалить словесные заполнители, отклонения от темы, повторения
- Преобразовать разговорную формулировку в письменную точность
- Консолидировать одну и ту же идею, выраженную несколько раз, в одно ясное утверждение
- Сохранять только уникальные, применимые знания

**Тест компрессии:** Если из документа знаний можно восстановить ход видео (кто что сказал, в каком порядке) — компрессия недостаточная. Документ должен содержать только знания, а не хронологию.

**Признаки недостаточной компрессии:**
- Главные идеи пронумерованы 1→2→3→4 в том же порядке, в котором спикер их озвучил
- Текст можно прочитать как «сначала он сказал X, потом Y, затем Z»
- Удаление любой единицы знания не влияет на понимание остальных (значит, она хронологический filler, а не знание)

**Тест хронологического порядка (обязательный перед фазой 3):**
Посмотрите на временные метки в секции «Главные идеи». Если они идут по возрастанию (02:30, 08:40, 18:00, 23:00, 34:00) — **вы следовали за видео, а не за темами.** Это провал.

**Как исправить:** Перегруппировать. Найти идеи, которые естественно связаны (например, «архитектура LLM-продуктов» и «generation-verification loop»), и поставить их рядом — даже если в видео они были в разных главах. Хронологический порядок = красный флаг.

**Область применения теста:** Тест компрессии применяется к секциям «Главные идеи», «Проблемы и решения», «Методология», «Ключевые инсайты». Секция «Виртуальные главы» не подлежит компрессии — она служит навигационной карте и intentionally сохраняет хронологическую структуру.

### 2.4 Процесс извлечения по категориям

**Обязательная структура каждой единицы знания** (идея, проблема, инсайт, методология):

```markdown
### [Название] 🗣 / 👁
[Сжатое описание — что именно утверждается]
- **Контекст:** для кого, в какой ситуации
- **Тип пользы:** Functional / Social / Psychological
- **Временная метка:** MM:SS
- **Источник:** 🗣 (verbal) / 👁 (visual — если знание извлечено из слайда/диаграммы)
```

**Единицы знаний без этих полей — незавершённые и не проходят quality gate.**

Формат с примерами — см. `references/templates.md`.

Процесс для каждой категории:

1. **Главные идеи:** Прочитать каждую виртуальную главу → выделить 1-3 главные идеи → записать с компрессией → пометить источник (🗣/👁)
2. **Проблемы:** Выделить проблемы, которые видео решает/описывает → записать с контекстом и решениями → связать с визуальными демонстрациями
3. **Предпосылки:** Выделить явные и неявные предположения спикера. В видео предпосылки чаще всего формулируются в первые 2-3 минуты — спикер задаёт контекст, озвучивает "очевидные" вещи. Искать: фразы вроде "we all know...", "obviously...", "the assumption here is...", а также неявные допущения (спикер считает что-то данностью без обоснования). Определить условия применимости → записать
4. **Последствия:** Выделить описанные и потенциальные последствия → записать
5. **Методология:** Выделить пошаговые процессы → для туториалов — извлечь из визуального канала → записать в формате инструкций
6. **Инсайты:** Выделить неожиданные идеи → пометить источник (🗣 verbal / 👁 visual) → записать с применением

## Фаза 3: Структурирование знаний

### 3.1 Шаблон документа знаний

Полный шаблон → `references/templates.md`. Краткий вид:

````markdown
# {Название видео} — Документ знаний

## Метаданные
- **Источник:** YouTube URL / путь к локальному файлу
- **Канал:** Название канала
- **Спикер(ы):** Имя (контекст: должность, релевантный опыт)
- **Дата публикации:** Дата
- **Длительность:** XX:XX
- **Тип:** Lecture / Interview / Review / Tutorial / Vlog / Short
- **Плотность:** High / Medium / Low
- **Язык:** Язык оригинала

## Краткое содержание (3-5 предложений)

## Виртуальные главы
- [MM:SS–MM:SS] Тема 1
- ...

## Главные идеи
[Извлечено, сжато, с метками источника: 🗣 verbal / 👁 visual]

## Проблемы и решения

## Методология в действии
[Для туториалов/демо: последовательность шагов из визуального + аудио-канала]

## Ключевые инсайты

## Визуальные знания
[Полный уровень: индекс кадров + описания | Лёгкий: «Кадры извлечены в keyframes/, анализ не проводился» | Пропущен: «Недоступно (тип видео: ...)»]

## Применимость

## Связи
[Связано с / Противоречит / Дополняет — другие документы в базе знаний]
````

### Правила размещения inline-изображений

**Применяются только для «Полного» уровня визуального канала** (Tutorial/Demo, Review, Short). Для «Лёгкого» и «Пропущенного» — inline-изображений нет.

Изображения встраиваются **рядом с соответствующим знанием**, но не должны ломать чтение:

- **Максимум 1 изображение между двумя абзацами текста.** Если нужно показать 2+ визуальных элемента — описать их текстом, одно проиллюстрировать.
- **Каждое изображение должно иметь текст до и после.** Стена из 3+ изображений подряд = нарушение.
- **Секция «Визуальные знания» — обязательна** для полного уровня: для каждого значимого кадра указать timestamp, тип и описание визуального знания. Inline-изображения дополняют эту секцию, не заменяют.
- **Inline-изображения — только со значимым визуальным содержанием.** Talking head, пустой слайд с заголовком, общие фотографии — не включать.

### 3.2 Организация файлов

База знаний расположена в `~/Documents/knowledge-base/`.

```
~/Documents/knowledge-base/
└── videos/
    └── {video-title}/
        ├── source/
        │   └── {video-file or URL-reference.md}
        ├── transcript.txt
        ├── keyframes/
        │   ├── 00-02-30_diagram.png
        │   └── 00-15-00_demo.png
        └── {video-title}_knowledge.md
```

**Почему так:**
- Плоская структура по названию видео — канал, дата и URL в метаданных документа, а не в пути
- `source/` хранит оригинал для повторного извлечения или смены шаблона
- `keyframes/` — только значимые визуальные кадры (не talking head)
- `transcript.txt` — чистый транскрипт для повторной обработки

## Quality Checklist

Полные чеклисты → `references/quality-checklists.md`. Краткий вариант:

### Перед извлечением
- [ ] Источник получен (транскрипт + визуальный канал по уровню)
- [ ] Визуальный канал выполнен по уровню: Полный (классифицирован), Лёгкий (кадры в keyframes/), Пропущен (тип Interview/Vlog)
- [ ] Тип видео определён
- [ ] Виртуальные главы идентифицированы
- [ ] Информационная плотность оценена
- [ ] Оригинал видео/транскрипта сохранён в `source/`

### После извлечения
- [ ] Каждое знание проходит Armament Test (можно использовать как аргумент)
- [ ] Каждая единица знания имеет: Контекст, Тип пользы, Временную метку, Источник (🗣/👁)
- [ ] 👁 маркеры использованы для знаний, извлечённых из визуального канала (только для полного уровня)
- [ ] Принцип компрессии применён (документ значительно плотнее видео)
- [ ] Инсайты проходят усиленный banality test: каждый — контринтуитивен, не звучит как заголовок TechCrunch
- [ ] **Тест хронологического порядка:** временные метки в «Главные идеи» НЕ идут строго по возрастанию (если 02:30 → 08:40 → 18:00 → 23:00 → 34:00 — это провал)
- [ ] **Дедупликация:** одна мысль — одна секция. Нет повторов между «Проблемами» и «Инсайтами»
- [ ] **Визуальная верификация** (только полный уровень): каждый кадр, включённый в документ, проверен через Read tool — нет talking heads, контент читаем, кадр совпадает с темой секции
- [ ] **Тест «закрой транскрипт»** (только полный уровень): каждый кадр в секции «Визуальные знания» содержит знание, недоступное из аудио

### После структурирования
- [ ] Документ знаний следует шаблону
- [ ] **Все секции присутствуют:** Метаданные, Краткое содержание, Виртуальные главы, Главные идеи, Проблемы и решения, Методология в действии, Ключевые инсайты, Визуальные знания, Применимость, Связи. Пустые секции помечены «Не применимо (причина)»
- [ ] Секция «Визуальные знания» заполнена по уровню визуального канала:
  - Полный: содержит только визуальные знания (не подтверждения) — пройден тест «закрой транскрипт»
  - Лёгкий: содержит пометку «Кадры извлечены в keyframes/, визуальный анализ не проводился»
  - Пропущен: содержит пометку «Недоступно (тип видео: ...)»
- [ ] Метаданные полные (включая «Спикер(ы)»)
- [ ] Практическое применение определено
- [ ] Документ читаем без просмотра исходного видео
- [ ] Оригинал видео/транскрипта сохранён в `source/`

# YouTube: субтитры и информация
yt-dlp --list-subs URL

yt-dlp -f "best[height<=720]" URL -o video.mp4
yt-dlp -x --audio-format mp3 URL

ffmpeg -i video.mp4 -vn -acodec mp3 audio.mp3

parakeet-mlx audio.mp3 --output-format txt    # → чистый текст
parakeet-mlx audio.mp3 --output-format json   # → с word-level timestamps
parakeet-mlx audio.mp3 --output-format vtt    # → WebVTT субтитры

# Ключевые кадры — Лёгкий уровень (Lecture: threshold 0.5)
ffmpeg -i video.mp4 -vf "select=gt(scene\,0.5)" -vsync vfr keyframes/scene_%04d.png
