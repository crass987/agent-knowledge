# infostyle: режим «Восстановление» + обогащение редактурой (Беззубов)

- **Дата:** 2026-06-24
- **Статус:** одобрен устно, ожидает review спеки
- **Репозиторий:** `agent-knowledge` (скиллы; NOT Astra meta-repo)
- **Источники решений:** сессия 2026-06-24 (книга Беззубова извлечена в KB, commit `b05c4e5`)

## Контекст и проблема

Текущий `infostyle` предполагает, что на входе — **содержательно правый текст**, который надо
сформировать для читателя (полезное действие, архитектура, гигиена). Его маршрут: для НОВОГО —
архитектура → гигиена; для РЕДАКТУРЫ готового — гигиена первой.

Реальный рабочий вход чаще другой: **малочитаемый LLM-текст / ИИ-перевод**. У него другая
поломка — не «непонятно, зачем читать», а «вообще не читается»: кальки, канцелярит, вода,
отсутствие структуры, иногда галлюцинации. Инфостиль это обрабатывает плохо: он доверяет
контенту и бережёт голос автора, а для машинного текста голос некому беречь, а контент надо
sanity-проверять.

Дополнительно: редактурный канон Беззубова («Введение в литературное редактирование», 1997;
извлечён в KB) содержит принципы и именованные проверки, которые делают гигиену инфостиля
точнее (амфиболия, паронимы, однокорневой повтор, случайная рифма, дисфония) и добавляют
недостающее — метод диагностики и sanity-проверку контента.

## Решение

**Обогатить `infostyle` (Approach A), не плодить второй скилл.** Один скилл, два режима,
автовыбор режима по типу входа. Целевой стиль один (Ильяхов); режимы отличаются силой правки,
отношением к голосу автора и контенту, и наличием recovery-фронта.

Альтернативы (отвергнуты):
- **B — новый скилл `readable`**: отвергнут. Два скилла с одним конвейером = дублирование
  движка; для пользователя разница только в имени. (Сессия подтвердила: «зачем два скилла,
  которые прогоняют один конвейер».)
- **C — два агента (оркестр)**: отвергнут. Оверинжиниринг для обычного текста.

## Модель: два режима

Первый шаг скилла — **диагностировать вход** и выбрать режим.

| | **Формирование** | **Восстановление** |
|---|---|---|
| Вход | Своя мысль / человеческий текст | LLM-мусор / ИИ-перевод |
| Цель | Придать форму, служить читателю | Вытащить читаемый текст из обломков |
| Сила правки | Лёгкая–средняя | Тяжёлый рерайт |
| Голос автора | Сохраняем (метаслой core) | Не священен (автор — машина) |
| Контент | Доверяем | Sanity-проверяем (флагаем, не правим) |
| Кальки | Условно (только перевод) | Обязательно, первыми |
| Маршрут | архитектура → гигиена | диагноз → архитектура → переписывание → проверка |

Признаки машинного мусора (→ режим Восстановления): дефисные EN-ru гибриды, кальки-оборотчики,
канцеляризм («осуществляет», отглагольные, пассив), оценочные стоп-слова россыпью, плоские
абзацы без диагональной сканируемости, повторы. Если вход неоднозначен — уточнить у
пользователя или по умолчанию Формирование.

## Конвейер Восстановления

```
[мусорный LLM / ИИ-перевод]
  ① ДИАГНОЗ ──── что сломано и в какой мере (метод «найти→назвать→объяснить»)
  ② ЗАМЫСЕЛ ──── польза читателю, путь А→Б, структура  ← ГЕЙТ (нет пользы → рерайт с нуля)
  ③ ПЕРЕПИСЫВАНИЕ ── агрессивный рерайт: де-калька · канцелярит→глагол · стоп→факт ·
                    повторы/паронимы/амфиболия/дисфония → читаемый ЧЕРНОВИК
  ④ ПРОВЕРКА ──── sanity контента (факты/логику ФЛАГАЕМ `[непроверено]`, не правим)
                  + финальная гигиена (9 проходов infostyle)
[читаемый человеком текст]
```

Порядок стадий разрешает исходный вопрос «редактура или инфостиль первыми»: они не два блока,
а вплетены — диагноз+проверка = редактура (Беззубов), замысел = инфостиль-архитектура,
переписывание = обе школы.

## Что из редактуры интегрируется

1. **Метод диагностики** «найти → назвать → объяснить → исправить» (Беззубов K-054) — на фронте
   режима Восстановление.
2. **Именованные проходы гигиены** (общие для обоих режимов, в `hygiene.md`): амфиболия
   (синтаксическая двусмысленность от порядка слов), паронимы/ложная синонимия, однокорневой
   повтор, случайная рифма, дисфония (неблагозвучие, стечение шипящих/причастий).
3. **Кальки** — из условного прохода в обязательный внутри Восстановления (`translationese.md`
   становится ядром стадии ③, не условным хвостом).
4. **Sanity-проверка контента** (факты/логика) — флагаем `[непроверено]` / `[?галлюцинация]`,
   НЕ правим молча и НЕ выдумываем (Беззубов K-014: редактор видит фактическую ошибку, но
   исправить не может — это к автору/человеку).
5. **Этос режима**: для машинного входа голос не священен → агрессивный рерайт допустим (вплоть
   до переписывания абзацев целиком). Уточняет метаслой core («не вытравливать местоимения»),
   который остаётся в силе для человеческого входа.

## За рамками (не тащим)

- Полную таксономию ошибок Беззубова (фактические/логические/речевые со всеми подтипами,
  орфография, пунктуация, грамматические парадигмы склонения) — это справочный аппарат, не
  нужно для цели «читаемый текст». Источник целиком — в KB (`books/bezzubov/...`), ссылка из
  `sources.md`.
- Отдельный скилл `readable` / `редактура` (см. отвергнутые альтернативы).
- Оркестрацию сабагентами.
