## Фаза 0: Prerequisite Gate

### Матрица читаемости форматов

| Формат | Агент читает напрямую? | Что нужно |
|--------|----------------------|-----------|
| **epub** | Да | `unzip` — распаковать HTML-файлы, читать их |
| **fb2 (UTF-8)** | Да | Ничего — XML с текстом в `<p>` тегах |
| **fb2 (win-1251)** | Да, после iconv | `iconv -f windows-1251 -t utf-8 file.fb2` |
| **HTML** | Да | Ничего |
| **markdown** | Да | Ничего |
| **txt** | Да | Ничего |
| **docx** | Практически нет | `unzip -p file.docx word/document.xml` — 10:1 шум:сигнал, лучше pandoc |
| **rtf** | Нет | `textutil -convert txt` (macOS) или pandoc |
| **doc (OLE2)** | Нет | antiword / libreoffice |
| **pdf** | Нет | pandoc (текстовый) / tesseract (сканы) |
| **mobi** | Нет | calibre `ebook-convert` |

### Логика принятия решения

1. Формат в зелёной зоне (epub, fb2, HTML, md, txt) — читаем напрямую, конвертация не нужна и часто **вредит** качеству
2. Формат в жёлтой зоне (fb2 win-1251) — одна команда iconv, затем читаем
3. Формат в красной зоне (docx, rtf, doc, pdf, mobi) — → `references/conversion-guide.md`, затем вернитесь сюда

**Epub: консолидация (не конвертация).** HTML внутри epub может быть разбит на 30+ файлов. Для чтения агентом — объединить в порядке spine в один файл. Это `cat` в правильном порядке, не pandoc:

```bash
# Определить порядок файлов из spine → прочитать каждый HTML
unzip -o book.epub -d book_epub/
cat book_epub/toc.ncx  # порядок глав
# Читать HTML-файлы по порядку spine из content.opf
```

**Epub/fb2: изображения.** Извлечь из архива в `images/` с осмысленными именами (не `00003.png`, а `technology-adoption-life-cycle.png`). Изображения диаграмм — часть аргументации автора, могут использоваться в документе знаний.

**Почему конвертация вредит:** pandoc/calibre из epub генерируют CSS-артефакты (`{.calibreXX}`, `:::` div-обёртки), ломают пути к изображениям, загрязняют заголовки. Исходный HTML внутри epub — чище, чем сконвертированный markdown.

## Фаза 1: Первичное чтение

### 1.1 Анализ структуры

- Прочитать оглавление (если есть)
- Определить основные разделы и главы
- Выделить ключевые темы каждой главы

**Для fb2:** метаданные уже внутри файла — извлечь из `<title-info>`: автор, название, жанр, аннотация, язык, год издания. Не вводить вручную то, что уже структурировано.

**Для epub:** структура глав — в `toc.ncx`, метаданные — в `content.opf`. Оба файла парсятся напрямую.

```markdown
# Структура книги: [Название]

## Часть 1: [Название]
- Глава 1: [Тема]
- Глава 2: [Тема]
```

### 1.2 Классификация типа книги

Определите тип по двум осям — это определяет, на чём фокусироваться при извлечении.

**Ось 1: Предметная область**
Technology / Production / Marketing / Management / Psychology / Finance / Other

**Ось 2: Режим аргументации**

| Режим | Описание | Что выделять |
|-------|----------|--------------|
| **New model** | Автор предлагает новый фреймворк | Кросс-главные модели, компоненты, применимость |
| **Refutation** | Автор атакует существующую парадигму | Что опровергается, контринтуитивные инсайты, альтернатива |
| **Methodology** | Автор даёт пошаговую систему | Процессы, техники, инструменты, условия применения |
| **Narrative** | Автор рассказывает историю для доказательства точки | Сюжет, ключевые повороты, lessons learned |

Результат классификации записывается в метаданные документа знаний.

### 1.3 Восстановление нарративной дуги

**Цель:** Понять логику авторской мысли — не ЧТО сказано, а ПОЧЕМУ именно в этом порядке.

- Для каждой главы сформулировать one-sentence summary: "Глава N показывает, что..."
- Определить главный тезис главы — единственную мысль, без которой глава теряет смысл
- Определить ПОЧЕМУ эта глава идёт после предыдущей
- Определить какое вопрос/напряжение глава разрешает и какое новое создаёт

Формат — см. `references/templates.md` (Нарративная дуга).

### 1.4 Выделение ключевых концепций

- Выписать авторские термины и определения (не общеупотребительные — только концепции автора)
- Выделить ключевые модели и фреймворки (часто появляются в нескольких главах)
- Отметить важные цитаты и формулировки

## Фаза 2: Извлечение знаний

### 2.1 Категории извлекаемых знаний

| Категория | Что извлекать |
|-----------|---------------|
| **Главные идеи** | Ключевые мысли и выводы автора, центральные концепции |
| **Проблемы** | Что решает книга, что описывает, что возникает при применении |
| **Предпосылки** | Явные и неявные предположения автора, условия применимости |
| **Последствия** | Результаты применения, влияние на практику |
| **Методология** | Пошаговые процессы, методы, техники, инструменты |
| **Инсайты** | Неожиданные открытия, контринтуитивные идеи, озарения |

### 2.2 Cognitive Quality (Когнитивное качество)

Каждое извлечённое знание проверяется по четырём принципам:

**Принцип 1: Контекст и Применимость**
Знание не существует в вакууме. Для каждой идеи определите границы применимости:
- Целевая аудитория: Novice / Pro
- Состояние читателя: Crisis / Growth / Stacking
- Цель потребления: Solve / Learn / Confirm

**Принцип 2: Типология Пользы (Utility Taxonomy)**
- **Функциональная:** Улучшает процесс, экономит ресурсы
- **Социальная:** Повышает статус, авторитет, аргументацию
- **Психологическая:** Снижает тревогу, даёт уверенность, развлекает

**Принцип 3: Синтаксис Действия (Actionable Syntax)**
- Тест на визуализацию: Можно ли изобразить концепт как сцену?
- Грамматика: Субъект + Глагол + Объект. Избегать абстракций ("Оптимизация") в пользу действий ("Директор сокращает")
- Приземление: Абстрактные принципы должны иметь конкретные примеры (Case Studies)

**Принцип 4: Armament Test**
Можно ли использовать это знание как аргумент в дискуссии? Если знание нельзя превратить в убедительный аргумент без книги — оно недостаточно конкретно. Банальности ("надо планировать") не проходят этот тест.

### 2.3 Шаблон извлечения по категориям

Формат для каждой извлечённой единицы знания — см. `references/templates.md` (Формат извлечения знаний по категориям).

Процесс для каждой категории:

1. **Главные идеи:** Прочитать каждую главу → выделить 1-3 главные идеи → записать в формате шаблона → проверить связь между главами
2. **Проблемы:** Выделить проблемы, которые решает/описывает книга → записать с контекстом и решениями
3. **Предпосылки:** Выделить явные и неявные предположения автора → определить условия применимости → записать с контекстом
4. **Последствия:** Выделить описанные и потенциальные последствия → записать с контекстом
5. **Методология:** Выделить пошаговые процессы, методы, инструменты → записать в формате инструкций
6. **Инсайты:** Выделить неожиданные и контринтуитивные идеи → записать с контекстом и применением

### 2.4 Шаблон «Глава как аргумент»

**Применяется когда:** Режим аргументации = New model / Refutation / Narrative (когда автор выстраивает связный аргумент от главы к главе). В этом режиме единица извлечения — **глава**, а не тип знания.

Полный шаблон — см. `references/templates.md` (Шаблон «Глава как аргумент»).

Процесс:

1. Прочитать каждую главу целиком
2. Сформулировать one-sentence summary
3. Написать связное повествование о главной идее (2-3 абзаца), показав ход авторской мысли
4. Определить, что автор опровергает или с чем спорит
5. Определить логический переход от предыдущей главы
6. Выделить один ключевой инсайт
7. Выделить ключевой пример/case study
8. Определить, какое напряжение/вопрос глава создаёт для следующей
9. Добавить практическое применение
10. Выбрать 1-2 лучшие цитаты

## Фаза 3: Структурирование знаний

### 3.1 Выбор структуры

**Структура A: Каталог знаний** — для справочников, энциклопедий, наборов независимых тем. Нет связного аргумента от главы к главе. Полный шаблон → `references/templates.md`.

**Структура B: Понимание книги** — для narrative-driven книг (business/strategy/научно-популярные), где автор выстраивает связный аргумент. Полный шаблон → `references/templates.md`.

Структура B включает:
- Метаданные (с типом книги и режимом аргументации)
- Словарь концепций автора (до глав — без него теряется смысл)
- Ключевые модели и фреймворки (кросс-главные модели)
- Нарративная дуга
- Главы как аргумент (по шаблону 2.4)
- Карта инсайтов (без искусственных лимитов — столько, сколько книга даёт)
- Методология в действии

### 3.2 Структура библиотеки (для сценария 3)

**Правила именования:**
- Название папки и файлов — на языке оригинала книги (не транслитерация, не перевод)
- Автор указывается в имени папки
- Формат: `{author-last-name}/{book-title}/` — иерархия по автору
- Один файл знаний на книгу: `{book-title}_knowledge.md`. Историю изменений ведёт git, не номера версий в имени файла

```
knowledge-base/
└── books/
    ├── moore/
    │   └── inside-the-tornado/
    │       ├── source/                        # Архив оригинала
    │       │   └── inside-the-tornado.epub    # Исходный формат (не конвертировать)
    │       ├── inside-the-tornado.md          # Конвертированный текст (если нужен)
    │       ├── inside-the-tornado_knowledge.md # Извлечённые знания
    │       └── images/                        # Изображения из книги
    └── reicht/
        └── thinking-fast-and-slow/
            ├── source/
            │   └── thinking-fast-and-slow.epub
            └── thinking-fast-and-slow_knowledge.md
```

**Почему так:**
- `source/` хранит оригинал для повторного извлечения, перепроверки, или смены шаблона
- Иерархия по автору — стандарт библиотечной практики, упрощает навигацию при росте базы
- Название на языке оригинала — чтобы поиск по содержимому совпадал с названием папки
- Нет `index.md` — при структуре `author/title/` навигация через файловую систему. Поиск — `grep -r "pattern" knowledge-base/books/`

## Quality Checklist

Полные чеклисты → `references/quality-checklists.md`. Краткий вариант:

### Перед извлечением
- [ ] Формат в зелёной зоне (epub, fb2, HTML, md, txt) или сконвертирован из красной
- [ ] Структура понятна (оглавление, главы)
- [ ] Тип книги определён (предметная область × режим аргументации)
- [ ] Оригинал книги сохранён в `source/`

### После извлечения
- [ ] Каждое знание проходит Armament Test (можно ли использовать как аргумент?)
- [ ] Контекст определён (для кого, в какой ситуации)
- [ ] Тип пользы определён (Functional/Social/Psychological)
- [ ] Тест на визуализацию пройден (конкретный, «зримый» синтаксис)

### После структурирования
- [ ] Выбрана правильная структура (A или B)
- [ ] Все категории заполнены
- [ ] Метаданные полные
- [ ] Практическое применение определено
