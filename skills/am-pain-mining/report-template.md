## Легенды (общие для §§3–6)

**Confidence (уверенность находки):**
- 🟢 **observed** — прямо сказано/показано в транскрипте, есть цитата
- 🟡 **inferred** — вывод из сказанного, прямой формулировки нет
- 🔴 **hypothesis** — слабый сигнал; требует depth-interview, действовать как о гипотезе

**Природа боли (§5):**
- **Problem** — нанятый Solution выполняет Job ниже критериев (есть жалоба / негативная эмоция)
- **Barrier** — объективный факт блокирует граф работ (нет SSO, регион/реестр, формат данных, интеграция)
- **Tax Job** — навязанная ручная работа, которую клиент не выбирал (шквал алертов, ручная дедупликация)
- **State-A эмоция** — тревога / раздражение / страх *до* получения результата
- **fear** — прогноз Barrier/Problem/потери. Точный страх = это Barrier (работа с реальностью); неточный = работа messaging

**Тип разрыва (§6):**
- **Core-Job gap** — не выполняем эту Job совсем → строить
- **Barrier** — выполняем, но неисполнимо для сегмента → реальность (интеграция / сертификат / формат)
- **chain-break** — Core Job выполняем, но цепочка рвётся до или после → ремонт связи
- **value gap** — выполняем, но ниже критериев клиента → подтянуть к критериям

| Критерий | 0 | 1 | 2 | 3 | Балл | Почему |
|---|---|---|---|---|---|---|
| **Внутренний advocate** | Никто не поддерживает | Кто-то проявил интерес | Есть явный сторонник | Сторонник = ЛПР | _/3 | |
| **Сила боли** | Не озвучена | «Было бы неплохо» | Реальная проблема | «Надо срочно решить» | _/3 | |
| **Готовность продукта** | Не решает их задачу | Частично, есть gaps | Почти готов, мелкие gaps | Решает main ask | _/3 | |
| **Угроза конкурентов** | Есть сильная бесплатная замена | Конкурент уже в оценке | «У нас и так работает» | Нет реальной альтернативы | _/3 | |

**Итого: _/3 + _/3 + _/3 + _/3 = _/12**
