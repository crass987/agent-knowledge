# Knowledge Extraction

Три фазы: картирование → извлечение → структурирование.

**Cognitive quality** (4 принципа: контекст, типология пользы, синтаксис действия, armament test) — см. `book-knowledge-extraction`. Здесь — только адаптации для видео.

---

## Фаза 1: Картирование контента

Видео не имеют оглавления — структуру нужно **вывести**.

### Классификация типа видео

| Тип | Описание | Стратегия извлечения |
|-----|----------|---------------------|
| **Lecture/Educational** | Один спикер обучает | Временные темы, слайды как маркеры |
| **Interview/Podcast** | Два+ спикера | Тематические повороты, согласие/несогласие |
| **Review/Analysis** | Оценка продукта/идеи | Критерии, выводы, рекомендации |
| **Tutorial/Demo** | Пошаговая демонстрация | Последовательность действий, визуал = основа |
| **Vlog/Narrative** | Личная история | Таймлайн, ключевые повороты, lessons learned |
| **Short/Clip** | До 3 мин, высокая плотность | Одна тема, быстрое извлечение |

Тип записывается в метаданные документа.

### Виртуальные главы

Из транскрипта определить тематические сегменты:
- Переходные фразы ("Now let's talk about...", "Moving on to...")
- Визуальные изменения (новый слайд, переключение на демо)
- Для интервью: смена говорящего

```markdown
## Виртуальные главы
- [00:00–02:30] Introduction and context
- [02:30–08:15] Core concept: X
- [08:15–12:00] Case study: Y
```

### Информационная плотность

| Плотность | Признаки | Компрессия |
|-----------|----------|------------|
| **Высокая** | Плотный материал, мало повторений | Умеренная |
| **Средняя** | Типичный подкаст/интервью | Стандартная |
| **Низкая** | Много повторений, отклонения | Агрессивная |

### Gate 1→2

- [ ] Виртуальные главы с временными метками
- [ ] Плотность оценена
- [ ] Визуальный канал завершён по уровню
- [ ] **Запрещено (Полный уровень):** начинать извлечение до завершения визуальной классификации

## Фаза 2: Извлечение знаний

### Категории (адаптация для видео)

| Категория | Адаптация |
|-----------|-----------|
| **Главные идеи** | Компрессия повторений — спикеры повторяют 2-3 раза. Извлечь один раз. |
| **Проблемы** | Проблема = конкретная ситуация, где кто-то **не может достичь цели**. Описание характеристик — это идея, не проблема. |
| **Предпосылки** | Часто неявные — спикер принимает без озвучивания. Искать: "we all know...", "obviously...", неявные допущения. |
| **Последствия** | Без изменений |
| **Методология** | Для туториалов: визуальная последовательность ЕСТЬ методология — извлечь шаги из визуального канала. |
| **Инсайты** | Пометить источник: 🗣 (verbal) или 👁 (visual) |

### Структура каждой единицы знания

```markdown
### [Название] 🗣 / 👁
[Сжатое описание]
- **Контекст:** для кого, в какой ситуации
- **Тип пользы:** Functional / Social / Psychological
- **Временная метка:** MM:SS
- **Источник:** 🗣 (verbal) / 👁 (visual)
```

Единицы без этих полей не проходят quality gate. Примеры → `references/templates.md`.

### Правила качества

**1. Дедупликация:** Одна мысль — одна секция. «Когнитивные дефициты LLM» в «Проблемах» → не повторять в «Инсайтах».

**2. Banality test (усиленный):** Инсайт звучит как заголовок TechCrunch или Хабра — удалить. Не проходят: «AI изменит всё», «нужно быть осторожным с AGI».

**3. Визуальное знание ≠ визуальное подтверждение:**
- **Визуальное знание** = знание, которого НЕТ в аудио (диаграмма без устного пояснения)
- **Визуальное подтверждение** = кадр, полностью описанный в транскрипте
- В секцию «Визуальные знания» — только визуальные знания

**Тест «закрой транскрипт»** (для каждого кадра в «Визуальных знаниях»):
Закройте транскрипт. Посмотрите на кадр. Можете описать по памяти транскрипта? Если да — это подтверждение, не знание.

**4. Inline-изображения** — проверка через Read tool перед включением. Подробности → `visual-channel.md`.

### Компрессия

Документ знаний **плотнее исходного видео**: 30-мин видео → 3-5 мин чтения (~1:6–1:10).

Как применять:
- Удалить словесные заполнители, отклонения, повторения
- Разговорная формулировка → письменная точность
- Одна идея, выраженная 3 раза → одно утверждение
- Сохранять только уникальные, применимые знания

**Тест компрессии:** Если из документа можно восстановить ход видео (кто что сказал, в каком порядке) — компрессия недостаточная.

**Тест хронологического порядка** (обязательный перед Фазой 3):
Временные метки в «Главные идеи» идут по возрастанию (02:30 → 08:40 → 18:00 → 23:00)? **Вы следовали за видео, а не за темами. Провал.**

Как исправить: перегруппировать. Найти связанные идеи и поставить рядом — даже если в видео они были в разных главах.

Область применения: «Главные идеи», «Проблемы и решения», «Методология», «Ключевые инсайты». «Виртуальные главы» не подлежат компрессии — они навигационная карта.

### Процесс по категориям

1. **Главные идеи:** каждая виртуальная глава → 1-3 идеи → компрессия → источник (🗣/👁)
2. **Проблемы:** проблемы с контекстом и решениями → связать с визуальными демо
3. **Предпосылки:** явные и неявные → условия применимости
4. **Последствия:** описанные и потенциальные
5. **Методология:** пошаговые процессы → для туториалов из визуального канала
6. **Инсайты:** неожиданные идеи → источник (🗣/👁) → применение

### Gate 2→3

- [ ] Каждая единица знания имеет: Контекст, Тип пользы, Временная метка, Источник (🗣/👁)
- [ ] Armament Test пройден
- [ ] Компрессионный тест пройден: хронологию не восстановить
- [ ] Хронологический порядок: метки НЕ идут по возрастанию
- [ ] Инсайты не содержат банальностей
- [ ] Все секции шаблона заполнены (или «Не применимо»)
- [ ] **Запрещено:** переходить к структурированию с незавершёнными единицами

## Фаза 3: Структурирование

### Шаблон

Полный шаблон → `references/templates.md`.

Все секции обязательны: Метаданные, Краткое содержание, Виртуальные главы, Главные идеи, Проблемы и решения, Методология, Ключевые инсайты, Визуальные знания, Применимость, Связи. Пустые — пометить «Не применимо (причина)».

### Организация файлов

```
~/Documents/knowledge-base/
└── videos/
    └── {video-title}/
        ├── source/{video-file or URL-reference.md}
        ├── transcript.txt
        ├── keyframes/{timestamp}_{description}.png
        └── {video-title}_knowledge.md
```

- Плоская структура по названию — канал, дата, URL в метаданных
- `source/` — оригинал для повторного извлечения
- `keyframes/` — только значимые кадры (не talking head)

### Output

- Документ знаний пишется на **русском**. Цитаты — на языке оригинала. Термины — язык оригинала с русским объяснением.
- Критерии готовности: структурировано, сжато (3-5 мин для 30-мин видео), условия описаны, связи указаны, документ читаем без видео, оригинал в `source/`
